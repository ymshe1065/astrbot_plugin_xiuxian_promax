<summary><b>本次更新 · v7.8.0（秘境与历练列表改版 / 筛选与折叠）</b></summary>

| 范围 | 变更 |
| --- | --- |
| 问题 | 秘境 45 档、历练 60 条平铺在一个滚动列表里：能进的埋在中间，想看某类材料只能一行行找，历练还完全不显示修为 —— 玩家无法判断「我该进哪个」。 |
| 秘境列表 | 改成三段：**当前可进 / 即将解锁（差 1~3 级）/ 尚未解锁**。可进段按「每分钟期望材料价值」降序，第一条标「最佳」，每行带产物与效率档（`灵植★★★`）、耗时、修为、灵石，`/秘境列表 灵植` 可按产物筛。 |
| 材料价值怎么算 | 用 `material_catalog` 目录价对掉落表求期望：Σ(权重 × 平均数量 × 单价) × 主掉落率 × (1 + 额外掉落率)。**只算材料**——掉落表里混的渡劫增益丹单件 30 万，算进去会把排序带偏。★ 以「当前可进入段最高效率」为 100%，所以列表第一条必是 ★★★。 |
| 历练列表 | 60 条压成「可走 / 未解锁」两段，可走段按**最新解锁优先**排列；每行补上「这一趟按你当前丹药符箓加成能拿到的修为」—— 这是旧版最缺的决策依据。`/历练信息 灵植` 可按产物筛。 |
| 推荐位 | 按产物轮转挑选，保证 6 条覆盖不同材料。高境界路线常常清一色「极高风险 + 全产物」，直接取收益前 6 等于没推荐。 |
| 网页端 | 新增发现型列表渲染：顶部筛选标签（带各分类计数）、分组可折叠、每行右侧按钮点一下直接进入/出发。数据走卡片 sidecar 的 `facets` / `groups` 字段，与 QQ 端的图片共用同一份排序结果。 |
| 参数候选 | `/探索秘境`、`/开始历练` 的候选列表同步只列当前可进入的，带材料档与修为，不再铺 45 条含锁定的选项。 |
| 版本与数据库 | 插件 **v3.43.0** / 游戏及帮助 **v7.8.0**；无表结构更新，数据库仍为 **v61**。 |

<summary><b>v7.7.0（修为公式重构 / 历练主产修为 / 秘境材料副本）</b></summary>

| 范围 | 变更 |
| --- | --- |
| 修为尺子 | 闭关、历练的修为全部改为「按本境界突破需求折算」，不再是固定基数。无任何加成闭关约 **400 小时**突破一个大境界，灵根/功法/丹药/符箓全满约 **20 小时** —— 突破耗时与境界无关，不会越后期越卡。 |
| 分工重划 | **灵根与功法只在闭关生效**；丹药与符箓同时作用于闭关与历练；秘境不吃任何修炼加成。灵根倍率整体上调（0.5~2.5 → **0.7~3.2**），功法上限 80% → **130%**，80 条功法的修为倍率 ×1.6，临时加速丹 ×1.6（+40%~+200%），符箓修炼加成 0.18~0.34 → **0.28~0.55**。 |
| 历练 · 修为主产地 | 修为 = 突破需求 × **1.656%/小时** × 时长 × 丹药符箓加成，按「闭关同境界全加成 × 0.9」设计，永远略低于闭关满配；**只吃丹药符箓**，灵根差的玩家也能跟上。路线时长压缩到 **15~30 分钟**。 |
| 历练 · 必须走完 | 取消分段小结，走完全程一次性结算；`/完成历练` 到点前只返回剩余时间，中途退出**本次无奖励**（不扣灵石、不加冷却）。 |
| 秘境 · 材料副本 | 修为压到象征量（单趟 50~12000，按境界段 × 档位），灵石维持原有量级；分段结算从历练**迁到秘境**（每 5 分钟小结 60% + 大结算 40%，掉落按 0.6/0.4 摊薄，整趟期望不变）。秘境不再触发奇遇。 |
| 奇遇 | 统一由历练产出，触发率 25% → **35%**；**超时不再消失**，自动按选项 [1] 结算并推送提示，后台每 60 秒扫描。 |
| 并发与一致性 | 秘境大结算改用 CAS 认领（`UPDATE ... WHERE type=EXPLORING`），手动结算与后台任务并发时只发一次奖；分段小结按 `ticks_done` 做 CAS；修复分段掉落未落库的顺序问题。 |
| 版本与数据库 | 插件 **v3.42.0** / 游戏及帮助 **v7.7.0**；复用现有 JSON 字段，无表结构更新，数据库仍为 **v61**。 |

</details>

<summary><b>v7.6.0（历练分段结算 / 中途退出无惩罚）</b></summary>

| 范围 | 变更 |
| --- | --- |
| 分段结算 | 历练不再等 30~60 分钟一次性结算：每 5 分钟自动发一个小结（小结合计约整趟 60%），走完全程再发一次大结算（剩余 40%，兼作完成奖励）。30 分钟路线 = 5 小结 + 1 大结算，60 分钟 = 11 小结 + 1 大结算。 |
| 产出翻倍 | 整趟修为/灵石为改版前的 **2.00 倍**（期望值实测 2.00~2.02），材料期望 **1.9~2.1 倍**；合体期顶级路线约 7.7 万材料价值/小时，与同期秘境（8.1 万/小时）基本持平，空手率 17% → 8%。 |
| 退出无惩罚 | 新增 `/退出历练`（旧 `/放弃历练` 保留）：随时可走，**已结算的小结奖励全部保留**，未走完的部分放弃，不扣灵石、不加冷却、不追加违约金。 |
| 推送与补算 | 后台每 20 秒扫描历练中的玩家，按出发时记录的会话主动推送小结；掉线期间错过的段落合并为一条「补算 n 段」，不会重复发奖。 |
| 结算内容 | 大结算统一处理宠物奇遇、探索符次数、路线休整冷却、悬赏进度、任务进度、称号计数与奇遇/善举；`/完成历练` 可随时补领。 |
| 兼容 | 升级前开始的一次性历练按已过时间自动接管（补算已到期段落），无需手动处理。 |
| 版本与数据库 | 插件 **v3.41.0** / 游戏及帮助 **v7.6.0**；`extra_data` 复用现有 JSON 字段，无表结构更新，数据库仍为 **v61**。<br>注：v7.7 起分段结算已迁到秘境，历练改回「必须走完才结算」。 |

## 📦 安装

### 1. 环境要求
- AstrBot **4.29.x**（网页聊天室适配器按 4.29.x 实测；更高版本需自行验证平台注册接口）
- Python 3.10+（插件）；AstrBot 4.29.x 本身要求 Python 3.12

### 2. 安装依赖
```
aiosqlite>=0.19.0
aiohttp>=3.9
Pillow>=9.0.0
tzdata>=2024.1
```

装到 **AstrBot 所在的 Python 环境**，不要装到系统 Python：

```bash
/path/to/AstrBot/venv/bin/pip install -r \
  /path/to/astrbot_plugin_xiuxian_promax/requirements.txt
```

> `aiohttp` 用于网页聊天室的 HTTP + WebSocket 服务；不启用聊天室时它仍被 AstrBot 依赖。

### 3. 部署插件
```
将本仓库放入 AstrBot 的 data/plugins/astrbot_plugin_xiuxian_promax
重启 AstrBot 即自动完成初始化与数据库建表（v60）
```

### 4. 配置（WebUI 可视化配置）
- `WHITELIST_GROUPS`：启用插件的群号（留空表示所有群聊都可用）
- `BROADCAST_GROUPS`：全服事件播报群号；留空时沿用 `WHITELIST_GROUPS`。若两者都为空，事件仍会生成，但群内收不到播报
- `BOSS_ADMINS`：管理员 QQ（生成世界Boss/开启团本/结束团本/开启魔潮/开启与结束天魔入侵/生成江湖事件/仙界管理）
- `IMAGE_CARDS`：图片卡片独立开关（含 `CARD_HELP` 帮助页、`STATIC_AUTO_REGEN` 内容变化自动重绘）
- `MARKET_NPC`：坊市NPC问价开关、随机间隔（默认约1小时）、问价上下限比例（默认 80%~120%）
- 其余数值项均有默认值

### 5. 旧版迁移
从 `astrbot_plugin_monixiuxian2` 或 `astrbot_plugin_xiuxian` 升级：首次启动**自动整体迁移数据**，玩家数据无缝保留。

### 6. 固定页图片生成
`/修仙帮助` 等固定列表页支持预生成图片，首次调用或内容/版本变化时自动重绘，并缓存到 `resources/generated/`：

```bash
# 列出所有固定页
python scripts/generate_static_images.py --list
# 生成帮助页（内容未变则复用）
python scripts/generate_static_images.py --page help
# 强制重绘全部固定页
python scripts/generate_static_images.py --all --force
# 运行离线测试（会自动生成并校验帮助页图片）
python -m unittest tests.test_static_images -v
```

## 🌐 网页聊天室（webroom）

插件内置网页聊天室：浏览器里多人实时群聊，使用**与 QQ 端相同的玩家存档和指令**。
页面与 WebSocket 由插件内的 `aiohttp` 服务直接提供，**无需 Node.js / npm，也无需单独启动前端进程**。

### 选择启动方式

| 场景 | 启动方式 | 机器人真实回复 | 适合 |
|---|---|:---:|---|
| 已有 AstrBot，正式使用 | WebUI「平台适配」新增 `webroom` | ✅ | 生产 |
| 本机没有 AstrBot，要完整链路 | `scripts/astrbot_local.sh start` | ✅ | 本地联调 |
| 只调页面/气泡/看板 | `scripts/dev_webroom.py --demo` | ❌（演示桩） | 前端开发 |

### 方式一：已有 AstrBot（推荐）

1. 按上面步骤安装插件和依赖，重启 AstrBot；
2. 打开 WebUI →「平台适配」→「新增」，类型选择 **`webroom`**；
3. 填写 `host=127.0.0.1`、`port=6198`，保存并启用；
4. 在插件配置中设置：

   ```json
   "ACCESS_CONTROL": {
     "WHITELIST_GROUPS": ["room_main"],
     "BROADCAST_GROUPS": ["room_main"]
   }
   ```

5. 浏览器打开 <http://127.0.0.1:6198/>，注册账号后默认进入主频道「原始仙界」。

> 主频道固定为 `room_main`，也是白名单与播报群要填写的房间号；私人仙界在网页内创建与切换，不需要改配置。不配白名单会导致网页指令被拒，不配播报群会收不到 Boss/拍卖/江湖事件广播。

### 方式二：本地完整运行时（脚本启动）

```bash
scripts/astrbot_local.sh start      # 启动 AstrBot + 聊天室
scripts/astrbot_local.sh status     # 6199 面板 / 6198 聊天室
scripts/astrbot_local.sh logs 80    # 查看日志
scripts/astrbot_local.sh restart    # 改代码/配置后重启
scripts/astrbot_local.sh stop       # 停止
```

运行时固定为 `~/.astrbot-runtime`（可用 `ASTRBOT_RUNTIME` 覆盖），插件以软链方式指向本仓库，修改代码后重启即可生效。首次从零搭建见[部署指南](docs/网页聊天室部署指南.md)。

### 方式三：只预览前端（不加载插件）

```bash
python3 -m venv .venv
.venv/bin/pip install "aiohttp>=3.9"
.venv/bin/python scripts/dev_webroom.py --demo
```

演示账号 `demo / demo123456`。该方式用桩替代 AstrBot 与插件，**不会执行修仙指令、不读写真实存档**，仅用于调 UI；默认也占用 6198，使用前先停掉正式服务或加 `--port 6200`。

### 端口与验证

| 服务 | 默认端口 | 说明 |
|---|---|---|
| 网页聊天室 | `6198` | 页面 + WebSocket + `/media` 图片 |
| AstrBot 面板 | `6199`（脚本） | 配置文件里的 6185 会被 `astrbot run -p 6199` 覆盖 |

```bash
curl -s http://127.0.0.1:6198/api/health
# {"ok": true, "adapter": true, "accounts": 1, "rooms": {}}
```
