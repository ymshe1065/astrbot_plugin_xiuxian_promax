## 1. 目标与设计原则

### 目标
1. **战斗增益按地形分化**：军事线不再只有"全兵种攻击 +2%"，而是分森林/高地/河流/沼泽/城墙/关隘给差异化攻防。
2. **带兵多少差异化**：军事线新增"大军团 / 精锐小队"两种取向，兵力高于/低于阈值时触发不同加成。
3. **经营线按资源分化**：农政线把"全据点产出 +4%"拆成"谷田粮草 +X%、矿脉精铁 +Y%、坊市铜钱 +Z%、灵石 +W%"，让资源点各有专精。
4. **主推方向由玩家自选**：沿用现有"自行选择研究哪条线、把哪条线点高"的自由选择机制，**不新增 focus 主推系统**——玩家通过投入哪条线、点到几级，自然形成各自的主推 Build。

### 设计原则
- **向后兼容**：`tech_json` 现有结构不动，不新增字段；`tech_effects()` 返回键保持"只增不改"，旧调用方（`_army_sim` / `_step_distribute_output` / 计略 / 粮耗等）无需改动即可继续工作。
- **配置驱动**：效果数值从 `config/strategy_config.json` 的 `tech.effects_values` 读取，代码提供默认回退（等价今日硬编码值），**既有单测（`test_strategy_hex.py::test_tech_effects` 无 config 调用）不破**。
- **与所在地机制同口径**：地形/带兵/资源三轴均复用 v81 已落地的 `potential` / 据点类型 / 驻守状态 / 产出乘区，不与"地形决定发展上限"冲突（详见 §7）。

## 2. 总体架构改动

### 2.1 `tech_json` 结构
**保持不变**：
```
tech_json = {
    "military": 3, "agri": 2, "stratagem": 1,   # 各线等级
    "points": 123,                               # 研究任务产出的科技点
    "pending": {...},                            # 进行中的研究
}
```
- 不新增字段、不需要 DB 迁移。

### 2.2 `tech_effects()` 签名与返回
```python
def tech_effects(tech_json, max_lvl=5, tcfg=None) -> dict[str, Any]:
```
- 新增参数 `tcfg`（`tech` 配置块，缺省用内置默认值），等级计算仍用现有 `tech_level()`。
- 返回键**只增不改**，新增三类（见 §3），下游按需 `.get(..., 默认)` 取用。

### 2.3 配置驱动改造
`config/strategy_config.json` 的 `tech` 块新增：
```json
"tech": {
  "lines": ["military", "agri", "stratagem"],
  "levels": 5,
  "cost_iron": [500, 1000, 2000, 3500, 6000],
  "cost_coin": [500, 1000, 2000, 3500, 6000],
  "base_hours_per_level": [8, 16, 24, 32, 40],
  "stat_speed_divisor": 10,
  "stat_speed_pct": 0.05,
  "big_army_threshold": 2000,         // 大军团阈值（兵力 ≥ 此值）
  "small_army_threshold": 800,        // 精锐小队阈值（兵力 ≤ 此值）
  "effects": { ... },                 // 现有：展示文案（保留并扩充）
  "effects_values": {                 // 新增：实际数值（line → level → {key: value}）
    "military": { "1": {"atk_bonus": 0.02, "terrain_atk_mult": {"plain": 0.03}}, ... },
    "agri": { ... }, "stratagem": { ... }
  }
}
```
- `tech_effects()` 优先读 `tcfg["effects_values"]`，缺失项回退内置默认（= 今日数值），保证兼容。

## 3. 三线逐级效果（核心）

> 说明：数值为**建议值**，全部落 `effects_values` 可调。括号内为**生效条件**。
> 「地形」指 hex 战斗地形（`highland/forest/river/swamp/wall/gate`），与大地图行军的 `mountain` 无关。

### 3.1 军事线（兵学）——地形轴 + 带兵轴

| 等级 | 名称 | 基础效果（保留） | 新增：地形分化 | 新增：带兵分化 |
| --- | --- | --- | --- | --- |
| L1 | 军制 | 全兵种攻击 +2% | 平原攻防 +3% | — |
| L2 | 攻城 | 破城槌造价 -30% | 城墙/城门（wall/gate）伤害 +10% | 带兵 ≥ 2000 时攻城槌效率再 +5% |
| L3 | 地利 | 全兵种攻击 +4%（累计 6%） | 高地攻 +8% / 森林防 +10% / 涉水（river/swamp）防御 -20%→-10%（减免） | — |
| L4 | 守备 | ZOC 拦截伤害 +25% | 城墙/关隘守军防御 +10% | 带兵 ≤ 800 时：机动 +1 边当量、先手 +5 |
| L5 | 军势 | 包抄系数 +5%（夹击 1.20/合围 1.35） | 全地形攻击 +3%（兜底泛用） | 带兵 ≥ 3000 时攻击 +5%（攻势碾压） |

**新增返回键**：`terrain_atk_mult`、`terrain_def_mult`（dict[地形→float]）；`big_army_atk_bonus` / `big_army_siege_bonus`（≥阈值）；`small_army_move_bonus`（边当量）/ `small_army_init_bonus` / `small_army_def_bonus`（≤阈值）。

### 3.2 农政线（经营）——资源轴

| 等级 | 名称 | 基础效果（保留） | 新增：资源分化 |
| --- | --- | --- | --- |
| L1 | 劝农 | 全据点产出 +4% | 谷田（grain 型）粮草产出 +10% |
| L2 | 漕运 | 军团粮耗 -10% | 全势力粮草总产出 +10% |
| L3 | 冶矿 | 全据点产出 +8%（累计） | 矿脉（mine 型）精铁产出 +15% |
| L4 | 商路 | 运粮队机动 +1、被劫损失 -50% | 坊市（market 型）铜钱产出 +10% |
| L5 | 屯田 | 断粮抵抗 +2 tick | 灵石产出 +5%、全资源产出再 +2% |

**新增返回键**：`resource_output_mult`（dict：coin/grain/iron/gold）；`node_type_output_mult`（dict：city/pass/mine/grain/market/branch）。
- 资源乘区 = `global output_bonus（保留） × resource_output_mult[资源] × node_type_output_mult[节点类型]`，三者叠乘。
- 钩子点：`_step_distribute_output`（`strategy_manager.py:4339`）的 `gain_coin/gain_grain/gain_iron` 与灵石 `gross` 计算处，`mult` 后追加两乘区（玩家分支；NPC 分支沿用 §10.8 民心乘数，不接玩家科技）。

### 3.3 谋略线（计谋）——保持 + 轻度联动

| 等级 | 名称 | 效果（基本保留） | 新增联动 |
| --- | --- | --- | --- |
| L1 | 离间 | 计略成功率 +4% | — |
| L2 | 耳目 | 侦察精度提升（显示敌将职责与适性） | 侦察额外揭示目标据点 hex 地形（与军事地形科技协同） |
| L3 | 军略 | 托管 AI 智谋等效 +5 | 计略对带兵 ≥ 2000 的目标成功率 +3% |
| L4 | 鬼谋 | 计略冷却 -2 tick、暴露率 -15% | — |
| L5 | 反间 | 解锁反间（30% 概率反弹计略） | 己方计略被反间概率 -15% |

**新增返回键**：`scout_terrain_reveal`（bool）、`plot_bonus_vs_big_army`（float）、`counter_spy_defense`（float）。谋略线改动最小，仅补与地形/带兵的联动点。

## 6. 与所在地机制（v81 / 设计文档）的兼容性

| 机制 | 兼容处理 |
| --- | --- |
| 据点潜力 `potential`（1~5，地形决定发展上限） | 科技的资源/节点乘区是**产出侧乘数**，与潜力决定的"等级/守军/城防上限"正交，叠乘不冲突；不新增"科技提高潜力"（避免破坏"地形决定上限"的战略定位） |
| 城镇等级 +20%/级（`_step_distribute_output:4384`） | 科技资源乘区叠在等级乘区之后，`mult` 顺序：全局 × 等级 × 司徒 × 科技资源 × 科技节点类型 |
| 驻守/太守（§5/§6） | 不新增"科技要求驻守"约束 |
| 守军自然增长（§10.4） | 可选：军事 L4 守备给本势力据点守军恢复 +0.5%/tick（叠加在 `garrison.char_grow_pct` 之上）；不破坏 §10.4 的封顶逻辑（封顶在 `_step_recovery` 内钳制） |
| NPC 经济/民心（§10.7/§10.8） | 玩家科技**不作用于 NPC**；NPC 势力科技走建世预置（可选），NPC 决策/坊市/军费不读玩家 `tech_effects`，保持 §10.8 的"NPC 专属"边界 |
| 战斗地形两套命名 | hex `highland` vs 大地图 `mountain`：军事地形加成仅作用于 hex 战斗地形（`highland`），行军地形不接军事科技（避免与 `TERRAIN_MARCH_COST` 混淆） |

## 8. 实施顺序（一次评审后分阶段落地）

1. **规则层**：`tech_effects` 扩展签名 + 新增返回键 + `effects_values` 默认回退；`TECH_NAMES` 文案。
2. **配置**：`strategy_config.json` 补 `effects_values` 与带兵阈值参数、扩充展示文案。
3. **军事轴**：`_sim_view` 地形乘区 + `_army_sim` 阈值加成 + 自动会战语境地形 + `march_speed/initiative` 字段。
4. **经营轴**：`_step_distribute_output` 资源/节点乘区。
5. **谋略轴**：计略/反间/侦察联动。
6. **前端**：科技面板动态效果文案。
7. **版本与文档**：`README.md`、`metadata.yaml`、`misc_handler.py` 的 `/修仙帮助` 更新版本号（无新增指令则仅更新说明文案）；`tests/test_strategy_hex.py::test_tech_effects` 与相关 strategy 测试回归。

## 9. 测试要点

- 规则：`tech_effects` 新旧键并存；`effects_values` 缺失时回退默认；`tcfg=None` 不崩。
