## 0. 术语约定

| 术语 | 含义 |
| --- | --- |
| 所在地（location） | 角色当前所在的据点，存 `strategy_characters.location_json.node_id` |
| 驻守 | 角色 `location == 某据点` 且 `status ∈ {idle, task(本地任务)}`（执行本地任务时也视为驻守该据点） |
| 名册槽位 | 角色招募容量，即 `_char_cap_info().cap`（基础 + 据点数 × 每据点名额） |
| 大牢 | 据点级关押容器，容量 `captive.jail_slots_per_node`（当前默认 5），与名册容量相互独立 |
| 己方/联盟据点 | `owner_faction` 属于本势力或结盟势力的据点 |
| 出征中 | 角色随军团行军/围城，`location` 跟随军团 `node_id` |
| 国库（treasury） | 势力级资源池 `strategy_factions.treasury_json`（coin/grain/iron/gold/reserved_coin），NPC 军费/升级/坊市均从此出 |

## 1. 现状与差距

当前代码里“所在地”是半成品：

1. `location_json` 已存在并存储 `node_id`（俘虏还存 `home_faction/home_owner/transfer_to`）。
2. `dispatch_task` / `create_army` 目前是**隐式传送**：直接写 `location = 目标据点`，不校验角色是否真的在那里。
3. 疗伤任务 `_heal_chars_at_node` 已按据点结算（只治“人在该据点”的角色，无落点的空闲角色视为主城）。
4. 新招募角色 `location` 为空（靠 `or 主城` 兜底）。
5. 太守的城防 +10%（`_attack_node`）与民心恢复 ×2（`_step_recovery`）目前只校验“任命且存活未离队”，**不校验太守是否驻守本城**。
6. 俘虏已用 `status='captive' + imprisoned_node_id` 存于 `strategy_characters`，且 `_roster_count` 已排除俘虏（不占名册槽位）；但“下城能抓谁”只取**守城军团成员**，不取“城内驻守/做任务的其他角色”。

本次规划的核心：把隐式传送改造成显式所在地 + 约束，并补上抓将/民心/事件等联动。

## 2. 目标与范围

**做：**
- 显式传送（免费瞬移，仅限己方/联盟据点；围城可进不可出）。
- 任务、编军必须“人在该据点”；侦察/劫掠/运粮“所在地”与“任务目标”彻底拆开（落点记出发地）。
- 下城抓将改为“抓城内的人”，并明确大牢/名册槽位语义。
- 民心改为“每 tick 自然恢复”口径下的魅力驻守加成。
- 太守加成改为“驻守才生效”。
- 擂台/单挑应战者须位于擂台据点。
- 瘟疫/谣言据点级事件与“驻守角色”联动（免疫/加速恢复）。
- 城池机制：城镇等级（阶梯费用 + 建造时间）、建筑开放到 `mine/grain/market`、守军自然增长（上限看城镇等级）。
- NPC 城池发展（稳定期 + 国库付费 + 建造时间 + 节奏上限）、NPC 资源经济（军费 + 坊市真实资源）、NPC 行为逻辑与民心模型（含性格驱动支出偏好），见 §10.6 / §10.7 / §10.8。
- 守军自然增长：玩家驻守按武将/统率差异化加速（§10.4）。

**不做（明确范围外，见 §11）：**
- 互市、计略、寻访/侦察起点等不再与距离/所在城增加额外联动。
- 移动不设消耗/冷却（默认免费瞬移）。

## 3. 传送 / 移动模型

新增动作：`move_char(user_id, char_id, node_id)`。

规则：

| 项目 | 规则 |
| --- | --- |
| 消耗 | 免费，无冷却，无距离限制（瞬移） |
| 目标范围 | 仅**己方 / 联盟据点**（`owner_faction ∈ alliance_ids`） |
| 禁止目标 | 无主据点、敌方据点、遗迹（与太守/任务口径一致：遗迹不可作为人物落点） |
| 围城据点 | **可传送进入**（驻守/增援）；**不可传送离开**（解围走军团 `sortie`） |
| 受限状态 | `status ∈ {task, army, captive, transfer, wander, dead}` 不可移动；仅 `idle` 可移动 |
| 校验 | 目标据点在盟内、角色所属玩家在盟内、角色 idle |

补充：
- “围城中的据点不可直接出”：人物可用传送进入被围城据点，但不能传送离开；解围/出击走**军团**（`sortie`）。
- 无主/敌方据点只有通过“远征类任务/出征”间接触及，人物不直接落点（见 §4）。
- 主城作为默认“回城/出生”点；迁都后随之变化。

## 4. 所在地约束（任务 / 编军）

### 4.1 任务分两类

| 类别 | 任务 | 规则 |
| --- | --- | --- |
| 本地任务 | govern / farm / mining / trade / build / train / heal / seek / research / quest | 角色必须已位于**目标据点**（己方/联盟）；执行期间 `location = 目标据点`，结束留在该据点 |
| 远征任务 | scout / raid / supply(追行军军团) | 角色从**出发地**（己方/联盟据点）出发；执行期间 `location = 出发地`（不落敌方/无主据点）；结束后回到出发地 |

- 侦察/劫掠的目标仍可指向无主/敌方据点，但人物落点始终在己方/联盟，满足“不能直接进无主/敌方”。
- 运粮：起点为己方据点，交付对象是军团；结束后回起点。

### 4.2 编军

- `create_army`：主将 + 副将必须**都已位于该据点**（`location == node_id`）。
- 前端交互：若角色不在该据点，提示“是否传送到 X 后编军”（等价一次 move + 编军，走 §3 的传送校验）。
- 编军后：成员 `status='army'`，`location` 随军团 `node_id` 走；解散后留在最后停靠据点。

### 4.3 校验统一

- 在 `dispatch_task` / `create_army` 入口加位置校验；前端抽屉里的“编军/派遣”下拉只显示“位于该据点”的角色（或标记“异地，需传送”）。

### 4.4 远征任务落点细则（侦察 / 劫掠 / 运粮）

> 这是“人物落点记出发地而非目标地”的详细说明，用于解决“不能直接进无主/敌方据点”的冲突。

**问题**：现有代码在任务结算时统一执行 `c.location = task.node_id`。本地任务没问题（`task.node_id` 就是己方据点），但侦察/劫掠的 `task.node_id` 是**敌方/无主目标**，结算后人物会“传送”进敌方/无主据点，违反“不能进无主/敌方”，也会被下城抓将误判为“在城内”。

**方案**：把“所在地”严格限定为“人物可被管理/驻守/加成/抓捕的据点”，永远只落在己方/联盟据点。远征任务只是“出勤”，人物不真的驻扎在敌方；用 `status='task'` + 出发地表现“人在外”。

任务 payload 新增 **`origin_node_id`（出发地）**，在派遣时取角色当前 `location`（必须为己方/联盟据点）。三类远征任务的落点规则：

| 任务 | 目标 | 出发地 | 执行期间 `location` | 结算后 `location` |
| --- | --- | --- | --- | --- |
| 侦察 scout | 任意敌方/无主节点（揭示情报，8% 被俘） | 角色所在己方/联盟据点 | = 出发地 | = 出发地 |
| 劫掠 raid | 相邻敌方/无主据点（掠夺库存、民心 -8、反杀） | 角色所在己方/联盟据点 | = 出发地 | = 出发地 |
| 运粮 supply | 指定军团（驻扎即时到账 / 行军补粮队追击） | 己方据点 | = 出发地 | = 出发地 |

**结算落点回退**：若任务结束/召回时出发地已易主（沦陷/被转移），则落点改为**最近己方据点**（复用 `_nearest_own_node`）。

**被俘落点**：远征中被俘（侦察 8% 被俘等）走 §7 大牢，关押点取**目标据点**（若目标有主）或**最近敌方据点**；无主目标**不产生俘获**，改为被“残军/匪寨”击伤（已定稿 §16-4）。

**为什么这样安全**：
- 人物永不出现 `location ∈ 无主/敌方` 的非法状态；
- 下城抓将按 `location == 城` 抓人时，远征中的人物在出发地，不会被误抓；
- 侦察/劫掠的“目标”只存在于任务 payload，不污染所在地字段。

### 4.5 任务执行时长模型（普通任务每 h 结算 · 侦察/劫掠固定时长）

> 任务结算模型改造：普通任务改成“持续性、每小时结算直至主动停止”；侦察/劫掠保留“固定时长、到期才结算”。

**普通任务（govern / farm / mining / trade / build / train / heal / seek / research / quest 等，除 `scout / raid`）**
- 改为**持续性任务**：派出后不再有固定 `end_at`，而是**每满 1 小时结算一次**该小时收益；角色持续 `status='task'`，直到玩家**主动停止**。
- 结算粒度：每 tick 累计，满 `ticks_per_hour`（4 tick = 1h）发放一次（含产出 / 民心 / 经验 / 体力，按小时口径）。
- 主动停止：当前未满 1 小时的部分按比例结算（已取消“召回损失 50%”）。

**侦察（scout）/ 劫掠（raid）**
- 保留**固定时长**：派出时指定 h，**只有达成指定 h 后**才一次性获得收益（情报 / 掠夺）。
- 中途停止 / 召回：不结算收益。
- 被俘 / 反杀等仍按现有结算。

**连带改动**
- `dispatch_task`：普通任务不再传 `hours`（或 `hours` 仅作“默认单循环步长”语义）；`scout/raid` 仍传 `hours`。
- `_step_settle_tasks`：从“到期一次性结算”改为“满 1h 循环结算”；`scout/raid` 仍按 `end_at` 到期结算。
- 体力/成本口径：按小时持续扣，体力耗尽自动中断任务；派遣时扣的 20 点即首小时费用，首个整点结算只发产出、不重复扣体力。
- 协作任务（2 人 +15%）：停止时同时释放两人，结算仍 ×1.15。

## 5. 民心 = 每 tick 自然恢复（魅力驻守加成）

保持现有自然恢复骨架，新增“驻守角色按魅力提升恢复速率”：

```
每 tick 自然恢复步长（仅民心 < 80 时） =
    基础 1（太守驻守 → 2）
  + 擂将台等级（现有）
  + 魅力驻守加成
```

- **魅力驻守加成**：每名驻守角色 `status ∈ {idle, task(本地任务)}` 且 `location == 该据点`，贡献 `floor(魅力 / 25)` 点（每 25 点魅力 +1）。
- 单角色封顶 **+4**；单据点合计封顶 **+6**（建议值，见 §15）。
- 仍沿用现有 `≥80 每 tick 回落 1 到 80` 的规则，**不做 80+ 民心维持**（只做加速恢复）。
- 低民心哗变（<20 每 tick 5%）保留。

## 6. 太守驻守（加成收敛到“驻守才生效”）

- 太守的 **城防 +10%** 与 **民心恢复 ×2** 仅在满足“**驻守本城**”时生效：
  - `location.node_id == governor 所辖据点`
  - `status ∉ {army(在别处行军), captive, transfer, wander, dead}`
  - 太守在本城执行本地任务/空闲，均算驻守。
- 太守驻守额外给本城自然恢复 **+1/tick（固定）**（叠加在 §5 之上）。
- 太守出征/被俘/离间/调离/换阵营后，本城加成立即失效（现有自动清理逻辑已覆盖“清理任命”，本次补“因出征离开而暂停加成”）。
- 据点抽屉显示太守是否“驻守中/离城”。

## 7. 抓将与所在城（下城抓捕 + 大牢）

### 7.1 抓捕目标 = “城陷时在城内的人”

城陷（`city_fall` / 破城）时，抓捕候选池改为：

```
capture_pool = { 角色 c |
    c.location.node_id == 该据点.id
    and c.status ∉ {dead, captive, transfer, wander}
}
```

即：**守城军团成员 + 在城内 idle 的角色 + 在城内执行本地任务的角色 + 驻守太守**。

- 俘获判定仍沿用 `capture_check`（城陷 40% 等既有概率）。
- 被俘者自动从军团/任务中摘除（复用现有 `_detach_from_armies` / 任务作废逻辑）。

### 7.2 大牢（单独存放，不占名册槽位）

- 被俘者入**大牢**：沿用 `status='captive' + imprisoned_node_id`（落在破城据点，或按现有规则迁到最近己方据点）。
- 大牢容量 `jail_slots_per_node`（默认 5）**独立于名册容量**：俘虏不占用名册槽位（现状 `_roster_count` 已排除）。
- 俘虏**不参与**任何本城效果（不提供魅力驻守、不作为太守、不产出、不治疗他人）。
- 满员时仍按现有“就地驱逐”逻辑（返回原势力、忠诚 -5）。

### 7.3 正式招募（转换入册）

- 俘虏在大牢里先走“劝降/赎金/释放”等既有流程。
- **正式招募 = 转换入册**：新动作 `recruit_captive`，要求：
  - 俘虏归属/可招降条件满足（如忠诚低于阈值、或已劝降成功）；
  - **当前有空闲名册槽位**（`_roster_count < _char_cap_info().cap`），否则提示“名册已满，请先扩建/遣散”。
- 成功：扣空闲槽位，`status → idle`，`owner_user_id / faction_id` 改为招降方，`location → 己方最近/指定据点`，清空 `imprisoned_node_id / captor_faction`。
- 与现有 `persuade_captive` 的关系：建议拆分——
  - `persuade_captive`：只做**忠诚/归顺**前置（降忠诚、建立羁绊），不直接入册；
  - `recruit_captive`：正式入册（占用槽位）。
  - 若要保留旧交互，`persuade` 成功后可自动走 `recruit_captive`（但仍以“有空闲槽位”为前置）。

> 备注：“任务容量槽位”即**名册/角色容量槽位**（已确认 §16-1）。

## 8. 擂台 / 单挑

- **摆擂者**：摆擂时须位于擂台所在据点（`arena` 建筑所在据点）。
- **应战者**：应战时须位于该擂台所在据点（用户明确）。
- 前端在“应战”前校验，不在则提示“先传送到擂台据点”。
- 擂台据点判定：该据点建有 `arena`（擂将台）才可摆擂 / 应战；建世给 `city` 预置 1 级 arena（已确认 §16-6）。

## 9. 事件联动（瘟疫 / 谣言）

- **瘟疫类据点事件**（node 级，造成受伤/士气/民心 DOT）：
  - 位于该据点且有 **doctor（名医）特技**或**高政务**的驻守角色，可提供**免疫/加速恢复**（如：驻守角色受伤恢复 ×2、据点不再额外掉民心）。
  - 简化为：驻守角色人数 ≥1 时，瘟疫对该据点的影响减半；有 `doctor` 特技的驻守角色可令该据点免疫。
- **谣言类据点事件**（民心 -15、产出 -20%，3 tick）：
  - 驻守太守或高魅力驻守角色可**抵消/缩短**该 debuff（如：驻守太守 → 民心动摇减半，时长 -1 tick）。
- 结算口径统一走“驻守”定义（§0），避免与 §5/§6 冲突。

## 10. 城池机制（城镇等级 · 建筑开放 · 守军自然增长）

### 10.1 现状确认（代码口径）

- 据点类型：`city / pass / mine / grain / market / branch / ruin`（遗迹不可建设/升级/驻防）。
- `upgrade_node`（据点升级）：目前**仅 `city / pass`** 可升级；等级 1~5，上限取建筑最高等级（5）；花费 `5000×等级` 铜钱 + `500×等级` 精铁，**即时完成（无建造时间）**；升级后城防重置为 `city_defense_max(新等级)=1000×等级`。
- `build` / `upgrade_building`：目前**仅 `city / pass / branch`** 可建设；`mine / grain / market` 不能盖建筑。
- 新玩家 `starter_pack.home_node_types = ["branch","market","grain","mine"]`：出生点可能是 `market / grain / mine`，而这些类型既不能升级、也不能盖建筑——**这就是“非主城不能盖建筑”的根因**。
- 据点产出：`_step_distribute_output` 已含 `(1 + 0.2×(等级-1))` 等级乘区（+20%/级），即“等级加产出”已存在，只是升级范围没放开。
- 守军 `npc_garrison.troops`：
  - **玩家据点**：无自然增长，仅入城初始（`home_garrison=300`）/ 占领保留（受降 50% 等）。
  - **NPC 据点**（`_step_npc_ai`）：每 tick **+2%** 恢复（`max(1, cap×0.02)`），上限 **`等级 × 2000`**；被清空后进入重生倒计时（`respawn_hours=[48,96]`h），倒计时期间不回兵，到时直接恢复到 `等级×2000`，且仇恨记忆 ×1.2；士气恢复 `min(85, +2/tick)`。
  - 因此“守军上限看城池等级”的现成口径就是 **`等级 × 2000`**，本次玩家守军增长可直接对齐它。

### 10.2 城镇等级（单独每城等级，上限 = 据点潜力）

- 复用 `node.level`，可升级范围从 `city/pass` 扩展到 **所有非遗迹的己方/联盟据点**（`city/pass/mine/grain/market/branch`）。
- **潜力（potential）**：每个据点在**地图生成时固定**一个潜力值（1~5），是玩家与 NPC 共同的等级上限；`upgrade_node` 上限从“建筑最高等级(5)”改为 `node.potential`。
- 潜力默认映射（按类型，模板可逐节点覆盖 `potential`）：

| 类型 | 潜力（建议） | 示例 | 说明 |
| --- | --- | --- | --- |
| city 仙城 | 5 | 碧落仙城 / 凌霄仙城 / 紫霄仙城 / 太虚仙城 | 天然大城 |
| branch 别院 | 5 | 御剑别院 / 丹鼎别院 / 万兽别院 | 宗门别院 |
| pass 关隘 | 4 | 剑门关 / 落雁隘 / 镇岳关 | 险要 |
| market 坊市 | 3 | 落星坊 / 百草坊市 / 琳琅坊市 | 商埠 |
| mine 灵脉 | 2 | 凝霜灵脉 / 赤铜灵脉 / 玄晶灵脉 | 资源点，低潜力 |
| grain 谷田 | 2 | 青禾灵谷田 / 白露灵谷田 / 金穗灵谷田 | 资源点，低潜力 |
| ruin 遗迹 | 1 | 上古剑冢 / 仙人遗府 | 不可建设/升级 |

- `upgrade_node` 改造：
  - 上限 = `node.potential`（原 `_node_level_cap()` 返回 5，改为读据点潜力）；
  - 消耗铜钱 + 精铁，**阶梯式递增**；
  - 新增**建造时间**：升级进入“建造中”状态（`node.construction = {to_level, end_tick}`），到期自动完成；建造中不可再次升级；被围城时**暂停**、易主时**作废（资源不退）**。
  - 完成时 `level += 1`，城防重置为 `city_defense_max(新等级)`（原 0 城防的 `mine/grain/market` 升级后开始有城防）。
- 等级效果（统一）：
  - 城防上限 = `1000 × 等级`；
  - 守军上限 = `2000 × 等级`（与 NPC 补兵口径一致，见 §10.4）；
  - 据点产出 = 现有 `+20%/级` 乘区（保留）。
- 战略含义：**仙城 / 别院成为兵家必争的据点（可升 L5，守军 10000）**，灵脉 / 谷田只是经济据点（L2 封顶，守军 4000），“地形决定发展上限”而非“谁占谁就能堆满”。

### 10.3 建筑开放

- `build` / `upgrade_building` 的可建设类型从 `city/pass/branch` 扩展到 **所有非遗迹的己方/联盟据点**（`mine/grain/market` 也可盖）。
- 遗迹仍不可建设/升级。
- 建筑效果维持不变（9 种建筑，等级 1~5）。

### 10.4 守军自然增长（方案 A：玩家 / NPC 统一口径）

> 已确认采用**方案 A**：统一“基础自然恢复 + 玩家驻守加成”，取消 NPC 专属重生倒计时。

- **上限统一**：双方均为 `2000 × 城镇等级`（NPC 现口径，玩家对齐）。
- **基础自然恢复统一**：双方每 tick `+2%` 上限（`max(1, cap×0.02)`），无需驻守角色（NPC 侧再乘 `民心/100`，见 §10.8）。
  - 被清空后**不自动重生**，靠此从 0 缓慢涨回（L1 从 0 回满约 `2000/(2000×2%)=50 tick ≈ 12.5h`）。
- **驻守加成（仅玩家）**：每名驻守角色 `+1%` 上限/tick（`max(1, cap×0.01)`）；武将（`role=general`）额外 `+0.5%`、统率 ≥ 80 的武将额外 `+1%`（即武将最高 `+2%/人`）；单据点合计封顶 `+5%` 上限/tick。
  - 用百分比而非固定值，避免高等级下 `+10/tick` 变得无感（L5 上限 10000 时 2% = 200/tick）。
- **取消 NPC 重生倒计时**：删除 `respawn_at` 的 48~96h 重生逻辑（`strategy_manager.py:5718`/`:5764`），NPC 与玩家同走 2% 基础恢复；`npc.respawn_hours` / `respawn_hatred` 配置作废。
- **围城期不增长（双方）**：仅无 `siege_state` 时增长；NPC 现有补兵逻辑未排除围城，本次一并对齐（否则守城方无限回血）。
- 约束：不超过上限；达上限后不再增长。
- 城陷/易主后按现有破城规则重置守军（`_capture_node` 保留比例，等级联动见 §10.6）。

### 10.6 NPC 城池发展（稳定期 + 国库付费 + 建造时间 + 节奏上限）

> NPC 财库现状是“只进不出”（详见 §10.7）。本节把“城池升级”作为财库的**第一个刚性出口**。
> 升级采用**四条件**：稳定期（占用时长，梯度递增）→ 国库付费 → 建造时间 → 每势力节奏上限。

#### 四条件

| 条件 | 规则 |
| --- | --- |
| ① 稳定期（占用时长） | 占领成功后（或上次升级完成后）**连续占领** `stabilize_hours[目标等级]` 才有资格升级；易主则清零重计 |
| ② 国库付费 | 从 `treasury_json` 扣 `5000×当前等级²` 铜钱 + `500×当前等级²` 精铁（与玩家同价，见 §10.5）；不足则暂缓 |
| ③ 建造时间 | 复用玩家 `construction_json`：`2×当前等级` tick 到期自动完成；建造中不可再次升级 |
| ④ 节奏上限 | 每势力**同时在建 ≤ 1 座**，两次启动间隔 ≥ `npc.develop.interval_hours`（默认 6h） |

> 说明：你提的“占用时长”仍在，但降级为**前置门槛**而非唯一触发；真正花钱的是国库，玩家与 NPC 规则因此对齐。

#### 数值表（已确认，按建议值）

| 目标等级 | 稳定期（连续占领） | 建造时间 | 铜钱 | 精铁 |
| --- | --- | --- | --- | --- |
| L1→L2 | 8h | 4 tick（1h） | 5,000 | 500 |
| L2→L3 | 18h | 6 tick（1.5h） | 20,000 | 2,000 |
| L3→L4 | 32h | 8 tick（2h） | 45,000 | 4,500 |
| L4→L5 | 50h | 10 tick（2.5h） | 80,000 | 8,000 |

- 单城 L1→L5 全程 ≈ **108h 稳定期 + 7h 建造 ≈ 4.8 天**（前提一直不失守）。
- 75 天赛季 + 串行节奏 ≈ 每势力完成 15 次左右升级，即 3~4 座核心城到 L4~L5，边缘城停在 L1~L2（符合“首都要塞化”观感）。

#### 选城优先级（确定性，不用随机）

```
候选 = 本势力据点：未在建 && 非围城 && level < potential && 稳定期已满 && 国库够
排序 = (potential desc, 是否与敌接壤 desc, NODE_OUTPUT_VALUE desc, level asc)
取第 1 个启动
```

#### 等级上限 = 据点潜力

- NPC 升级上限**不看主城**，一律取 `node.potential`（地图生成时固定，见 §10.2 潜力映射）。
- 高潜力据点（仙城/别院 = 5）才有资格升到 L5，灵脉/谷田（= 2）最多 L2。
- 玩家侧同样受潜力约束（§10.2），双方规则一致。

#### 易主联动（玩家与 NPC 同一规则，已确认）

| 易主方式 | 等级 | 在建工程 |
| --- | --- | --- |
| 强攻破城 | **-1（最低 1）** | 作废，资源不退 |
| 受降/劝降 | 保留 | 作废，资源不退 |
| 围城中 | 不变 | **暂停**（不推进不取消，解围续建） |

> 强攻 -1 同时解决：等待 NPC 升级再抢的收益变小、赛季内等级不通胀、城破有“重建成本”。玩家与 NPC 一律生效。

#### 落地要点

- 字段：`strategy_nodes.construction_json`（`{to_level, end_tick, started_at, by}`）+ `develop_ready_at INTEGER`（下次可升级时间，合成“稳定期 + 节奏间隔”）。
- 节奏计数：`world.data["npc_develop"] = {fid: {last_start_at, building_node_id}}`。
- tick 新增 `_step_npc_develop(world)`，插在 `_step_npc_ai` 之后、`_step_demon_tide` 之前（`strategy_manager.py:3748` 附近）。
- 到期结算：`level += 1`、`defense = 1000×level`、`develop_ready_at = now + stabilize_hours[新等级+1]`；围城期不推进。
- 配置：`config/strategy_config.json` 的 `npc.develop` 子块（`stabilize_hours / build_ticks / interval_hours / max_building`）。

### 10.7 NPC 资源经济（财库闭环：军费 + 坊市真实资源）

> 目标：把 NPC 从“凭空造兵、凭空造货”改成**真实资源循环**——
> 据点产出 / 任务 → 国库 → 军费 / 升级 / 坊市 → 扩张 → 更多产出。

#### 资源闭环

```
据点产出 / 任务 / 灵石 ──▶ 国库 (coin / grain / iron / gold)
                               │
     ┌───────────┬─────────────┼──────────────┬─────────────┐
     ▼           ▼             ▼              ▼             ▼
  出征动员    城池升级      坊市收购       坊市挂单      守军恢复
 (coin+行粮) (coin+iron)   (coin)        (真实库存)    (免费=生产)
     │
     ▼
  攻城占地 → 更多据点产出 → 循环
```

#### 军费模型（出征动员 + 行军维护）

| 项 | 规则 | 备注 |
| --- | --- | --- |
| 动员费（一次性） | 国库扣 `troops × mobil_coin_per_100`（默认 500，即 5 铜/兵） | = 玩家募兵铜钱价（剑盾 5 铜/兵，`R.TROOP_TYPES`） |
| 招募粮耗（一次性） | 国库扣 `troops × mobil_grain_per_100`（默认 100，即 1 粮/兵） | 对齐玩家招募粮耗结构，量减半避免 NPC 早期缺粮 |
| 携粮（出征时拨付） | `army.grain = min(国库粮, troops × carry_grain_per_100)`（默认 100，即 1 粮/兵） | 复用 `_spawn_npc_army` 的 `grain` 字段，不再凭空 `troops×2` |
| 行军/围城维护（每 tick） | 复用 `_consume_army_upkeep` 消耗 `army.grain`；耗尽 → 断粮掉士气/逃兵（现有） | NPC 军团本就走 `_step_march`，无需新管线 |
| 撤退/解散残粮 | 剩余 `army.grain` 退回国库 | 小改动，避免粮凭空蒸发 |

- **兵种价差**：动员费按势力 `personality.troop_pref` 对应兵种的 `recruit_coin/recruit_grain` 计算，不同 NPC 兵种成本不同；全局调参用 `npc.economy.mobilization_cost_mult`（默认 1.0）。
- **守财底线**：国库扣费后不得低于 `npc.economy.treasury_reserve`（默认 `{coin: 5000, grain: 2000, iron: 500}`），否则不出征 / 不升级 / 不收购，保住“东山再起”本金。
- **守军自然恢复免费**：§10.4 的 +2%/tick 视为“生产 / 募兵”，不花钱（与玩家驻守增长同口径），避免 NPC 因国库枯竭而永久瘫痪。
- **魔潮军团（faction -1）**：无国库，维持凭空生成（异象，不算真实势力）。
- **设计意图**：coin 是“募兵 / 动员”瓶颈（重、一次性），grain 是“战争燃料”瓶颈（持续、可断）。粮田因此成为战略目标——攻打 / 劫掠敌方粮田可饿死其大军（与现有运粮 / 劫掠 / 商路联动）。

#### 坊市（真实资源，与你正在改的坊市对齐）

| 行为 | 现状 | 目标 |
| --- | --- | --- |
| NPC 卖单 `_step_market_maker` | 货凭空生成（`strategy_p3_mixin.py:557`） | 只挂**真实持有**的 `grain / iron`（`recruit_token/intel` 无 NPC 产出源，不挂）；挂单时从国库扣库存（天然冻结），过期 / 撤单退回 |
| NPC 收购 `_step_market_offers` | 出价不校验国库；付款后物品蒸发（`:476`） | 出价前校验 `coin - reserved_coin ≥ amount×price`，并计入 `treasury.reserved_coin`（冻结）；成交时 `reserved_coin -= gross` 且**物品入国库**；过期 / 拒绝退回冻结 |
| 需求驱动 | 随机品类 | 按国库缺口选品：`grain < 阈值 → 优先收粮`；`iron 不足（想升级 / 征兵）→ 收 iron`；`token/intel` 由“行商”限量挂 |
| 卖单供给 | 随机 | `surplus = 库存 − reserve×N`，仅 `surplus > 0` 且超过 `surplus_sell_pct` 才挂牌 |

- 效果：矿多的 NPC 卖 iron 买 grain，粮多的卖 grain 买 iron，形成跨势力资源交换，价格由供需自然波动（为“坊市报价真实化”打底）。
- `reserved_coin` 是 `treasury_json` 里的一个 JSON 键，**无需迁移**。

#### 落地要点

- 改动集中：`_spawn_npc_army`（动员扣费 + 携粮拨付）、`_auto_retreat`（残粮退回）、`_step_market_maker` / `_step_market_offers` / `market_offer_accept`（真实库存 / 冻结 / 入库）。
- `_step_npc_ai` 出征决策增加“国库 / 底线”前置校验（`_step_npc_develop` 同理）。
- 新增配置块 `npc.economy`（`mobil_coin_per_100 / mobil_grain_per_100 / carry_grain_per_100 / treasury_reserve / surplus_sell_pct / offer_reserve_pct`）。
- 不新增动作、不新增表；仅 `treasury_json` 增 `reserved_coin` 键。

#### 性格驱动支出偏好

> 已确认一并实现：按势力 `personality` 对“动员 / 升级 / 坊市 / 赈济”施加乘数，让 NPC 有差异化行为（缺省字段 = 1.0）。

| 性格 | 动员底线乘数 | 升级倾向 | 坊市活跃度 | 赈济倾向 | 说明 |
| --- | --- | --- | --- | --- | --- |
| expansive 扩张 | 0.6 | 1.0 | 0.8 | 0.8 | 征伐阈值更低、更早动员 |
| developer 发展 | 0.8 | 1.5 | 1.0 | 1.2 | 更早升级城池 |
| trader 商贸 | 1.0 | 1.0 | 2.0 | 1.0 | 更勤快挂单 / 收购、价格更优 |
| hermit 隐逸 | 1.5 | 0.5 | 0.5 | 1.5 | 高守财底线、少折腾 |
| demonic 魔道 | 0.5 | 0.8 | 0.3 | 0.5 | 最好战、几乎不贸易、不赈济 |

- **动员底线乘数**：`treasury_reserve` × 该乘数 = 该势力实际守财底线（expansive/demonic 更敢花钱，hermit 更保守）。
- **升级倾向**：作用在 §10.6 稳定期（`stabilize_hours / 升级倾向`），developer 升级更快、hermit 更慢。
- **坊市活跃度**：作用在 §10.7 挂单 / 收购间隔与 `surplus_sell_pct`（活跃度越高，挂单越勤、越肯让价）。
- **赈济倾向**：作用在 §10.8 自动赈济触发阈值（倾向越高，民心略低就赈济）。
- 实现：`_step_npc_ai / _step_npc_develop / _step_market_*` 读 `faction.personality` 对应字段套乘数。

### 10.8 NPC 行为逻辑与民心模型

#### 现状行为（代码口径）

`_step_npc_ai`（`strategy_manager.py:5810`）目前每 tick 只做三件事：

| # | 行为 | 现状 | 问题 |
| --- | --- | --- | --- |
| 1 | 守军恢复 | +2%/tick 免费（上限 `2000×等级`） | 免费、不看民心、不看国库 |
| 2 | 被清空重生 | 48~96h 倒计时后回满（§10.4 已取消） | 将删除 |
| 3 | 出征决策 | `npc_utility` 评分，每 tick 每势力 ≤2 路 | 兵力/粮草凭空、不花国库、不花民心 |

NPC 目前**没有**：任务、建筑、科技、民心经营、征兵消耗、坊市真实化。出征决策只受性格里的 `aggression`（侵略性）与 `econ_weight`（经济权重）两个参数影响。

#### 目标：统一的“每 tick 决策循环”

```
每 tick，对每个存活 NPC 势力：
 1. 收入结算    —— 产出 × 民心乘数 → 国库（_step_distribute_output 改造）
 2. 民心结算    —— 自然恢复 / 哗变 / 围城掉民心（见下「民心模型」）
 3. 发展决策    —— _step_npc_develop：选一座满足四条件的城升级（§10.6）
 4. 经济决策    —— _step_npc_economy：按国库缺口挂单/收购（§10.7）
 5. 军事决策    —— _step_npc_ai：满足「国库 + 民心 + 守军」三重门槛才出征
 6. 善后        —— 撤退残粮退回 / 溃军重组（现有，微调）
```

- **决策优先级**：守财底线 → 发展 → 贸易 → 扩张。扩张排在最后——只有闲钱闲粮闲民心才打。
- **守财底线贯穿所有花钱行为**：低于 `treasury_reserve` 不出征 / 不升级 / 不收购 / 不赈济（赈济例外，见下）。

#### NPC 民心模型（核心新增）

> 民心（`node.morale`）从“被动掉血条”升级为 **NPC 的民力/人口资源**，把产出、守军、征兵、稳定串成一条闭环：
> **征兵 → 民心降 → 产出/补兵变慢 → 需要赈济恢复**，避免 NPC 无限征兵。

| 方向 | 规则 | 说明 |
| --- | --- | --- |
| 产出乘数 | 据点产出 × `0.5 + 民心/100×0.5`（民心 0→50%、100→100%） | 与 `R.task_yield_multiplier` 同口径；**NPC 专属** |
| 守军恢复 | `+2% 上限/tick × 民心/100`（民心 100→2%、50→1%） | 取代固定 +2%；**NPC 专属**（玩家走驻守加成） |
| 征兵消耗民心 | 出征动员每 100 兵 `-mobil_morale_per_100` 民心（默认 2，即 1000 兵 -20） | “抽丁”；民心低则无兵可征 |
| 动员民心门槛 | 民心 < 40 时只允许小规模动员（出兵 ≤ 守军上限 30%） | 防止民心枯竭时仍爆兵 |
| 民心恢复 | +1/tick 自然恢复（现有，`_step_recovery`） | 基础 |
| 自动赈济 | 民心 < 50 且国库 coin > reserve 时，自动花 `relief_coin_cost`（3000）→ +`relief_morale`（6），每日 ≤ `relief_daily_limit`（3） | 复用 relief 配置；给 coin 一个“维稳”出口 |
| 民心上限 | 100 + 擂将台（现有，NPC 不建建筑故恒 100） | 不变 |
| 哗变 | 民心 < 20 → 每 tick 5% 哗变（`riot_check`），守军 -30% | 现有，保留 |
| 围城 | 每 tick -2 民心（min 20，`strategy_manager.py:4254`） | 现有，保留 |
| 易主 | 重置 50（`:4462`） | 现有，保留 |

**战略含义**：民心成为玩家可打击 NPC 的“经济命脉”——谣言（-15 民心）、劫掠（-8 民心）、围城（-2/tick）持续压民心 → NPC 产出下降、守军恢复变慢、无法大规模动员 → 从“军事削弱”升级为“经济拖垮”。这补足了当前“打 NPC 只能打守军”的单一路径。

#### 落地改动点
