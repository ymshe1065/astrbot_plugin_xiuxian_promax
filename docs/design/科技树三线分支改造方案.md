# 仙域争霸 · 科技树三线分支改造方案

> 状态：**已实施（v4.5.0）**。
> 基线：插件 v4.4.1 / DB v83。现有科技为「军事 / 经营 / 谋略」三线各 7 级**线性等级**。
> 目标：把三线改为**主脉 + 支脉**的树状结构——主脉逐节解锁新的加成类别，支脉可反复升级、同类加成线性叠加。
> 关联文档：`docs/design/科技线扩展规划.md`（v4.3.13）、`docs/design/科技线扩展-三国志个性转化.md`（v4.3.14）。
> 落地记录见文末「§13 实施记录」。

## 2. 目标玩法定义

### 2.1 术语

| 术语 | 定义 | 玩家体感 |
| --- | --- | --- |
| 主脉 | 每条线一条顺序解锁的主干，共 7 节 | 每点一节，**多解锁一类加成** |
| 支脉 | 挂在主脉某一节下的可重复升级节点 | 每升一级，**同一类加成继续变大**（+5% → +10% → +15%） |
| 节点等级 | 主脉节点固定 1 级；支脉默认 0~5 级 | 支脉等级即叠加强度 |
| 解锁 | 主脉需前一节完成；支脉需其父主脉节点完成 | 树状前置关系 |

### 2.2 玩法示例（军事线）

```
军制 L1 ──┬── 平原战法 L1~L5   （平原攻防 +2%/级 → 最高 +10%）
          │
攻城 L2 ──┼── 攻城术   L1~L5   （城墙/城门伤害 +2%/级）
          │
地利 L3 ──┼── 林地战法 L1~L5   （林地防御 +5%/级 → +5% / +10% / +15% …）
          ├── 山地战法 L1~L5   （高地攻击 +5%/级）
          └── 涉水适应 L1~L3   （河/沼泽防御 +4%/级）
          │
守备 L4 ──┼── 城墙守备 / 关隘守备
          │
军势 L5 ──┼── 大军团 / 包抄战术
          │
军心 L6 ──┼── 士气整训
          │
无双 L7 ──┴── 单挑精研 / 俘获精研
```

- **主脉**决定「能不能吃到某类加成」：没点「地利」，林地/山地/涉水支脉全部锁定。
- **支脉**决定「这类加成有多强」：点了「地利」后，林地战法可以连点 5 级，林地防御从 +5% 叠到 +25%。
- 主脉原有 7 级效果**原样保留**，即使完全不点支脉，老玩家的战斗/产出口径不变。

### 2.3 设计原则

1. **效果键只增不改**：支脉写入现有 `tech_effects()` 返回键，`_army_sim` / `_sim_view` / `_step_distribute_output` / 计略等下游零改动。
2. **旧存档零迁移**：`tech_json` 是 JSON 列，只新增 `nodes` 子字典；旧字段 `military/agri/stratagem` 继续表示主脉等级。
3. **配置驱动**：节点树默认写在规则层，管理员可用 `tech.tree` 覆盖；费用/时长走配置数组。
4. **单次研究不破坏**：沿用「同一时间只有一项研究」的节奏（是否扩槽见 §11 待确认）。

## 3. 数据模型

### 3.1 `tech_json` 新结构（向后兼容）

```json
{
  "military": 3,
  "agri": 1,
  "stratagem": 0,
  "points": 240,
  "pending": {
    "line": "military",
    "node_id": "mil_b_forest",
    "kind": "branch",
    "by": "user_123",
    "char_id": 12,
    "char_name": "青云子",
    "finish_at": 1760000000,
    "exp": 120
  },
  "nodes": {
    "mil_b_forest": 2,
    "agr_b_grain": 1
  }
}
```

| 字段 | 说明 | 兼容性 |
| --- | --- | --- |
| `military/agri/stratagem` | **主脉等级**，仍是 0~7 整数 | 旧代码、旧测试、`tech_level()` 全部无感 |
| `nodes` | 新增：支脉 `node_id → 等级` | 缺失时按空字典处理，旧存档自动兼容 |
| `pending.node_id` | 新增：本次研究目标节点 | 旧 `pending` 无此字段时按「该线下一节主脉」处理 |
| `pending.kind` | `spine` / `branch` | 可选，缺省按 `node_id` 推断 |

> **无需 DB 迁移**：`strategy_factions.tech_json` 已是 JSON 文本列，新增键不涉及表结构。

### 3.2 节点定义（规则层默认，可配置覆盖）

```python
{
  "id": "mil_b_forest",
  "name": "林地战法",
  "kind": "branch",              # spine / branch
  "parent": "mil_s3",            # 父节点：支脉挂主脉；主脉挂前一节
  "max": 5,                      # 支脉等级上限；主脉恒为 1
  "effects": {"terrain_def_mult": {"forest": 0.05}},  # 每级增量
  "mode": "add",                 # add=线性叠加；mul=逐级叠乘
  "desc": "林地作战防御",
  "per_level_text": "+5%"
}
```

主脉节点（`kind: "spine"`）只需 `id / name / spine / parent / desc`；其数值仍由 `TECH_EFFECT_PATCHES` 按等级提供，避免两处维护同一份数值。

### 3.3 规则层新增 API

| 函数 | 职责 |
| --- | --- |
| `tech_tree(tcfg=None) -> dict[line, list[node]]` | 取节点树（`tcfg["tree"]` 按节点 id 合并覆盖默认 `TECH_TREE`，v4.5.5 起未列出的默认节点保留） |
| `tech_node_map(tcfg=None) -> dict[node_id, node]` | 节点索引 |
| `tech_nodes(tech_json) -> dict[str, int]` | 规整支脉等级（非法值归零、超上限钳制） |
| `tech_node_state(tech_json, node_id, tcfg=None) -> dict` | 计算 `level / max / unlocked / can_research / reason` |
| `tech_research_target(tech_json, line, node_id="", tcfg=None) -> dict` | 返回目标节点、费用、基础时长；主脉/支脉统一出口 |
| `tech_effects(tech_json, max_lvl=5, tcfg=None)` | **扩展**：先按主脉整数套旧补丁，再逐支脉叠加 `effects × level` |

`tech_effects()` 的调用方保持不变；仅补一处漏传配置的调用点（`managers/strategy_p3_mixin.py:1375`）。

## 5. 数值与叠加规则

### 5.1 支脉费用 / 时长（建议默认值）

| 支脉等级 | 铜钱 | 精铁 | 基础耗时 |
| --- | --- | --- | --- |
| L1 | 400 | 300 | 4h |
| L2 | 800 | 600 | 8h |
| L3 | 1,600 | 1,200 | 12h |
| L4 | 3,200 | 2,400 | 18h |
| L5 | 6,400 | 4,800 | 24h |

- 主脉费用/时长**沿用现有 7 档**（500~10,000 / 8~56h）。
- 角色智谋/政务加速、科技点抵扣 50% 时长的规则对主脉、支脉统一生效。
- 单条支脉点满：铜钱 12,400、精铁 9,300、基础 66h。

### 5.2 效果叠加优先级

```
最终效果 = 主脉补丁（按 line 整数，沿用旧表）
         + 支脉 effects × 支脉等级（线性键）
         × 支脉乘区 ^ 支脉等级（乘区键）
```

| 键类型 | 叠加方式 | 示例 |
| --- | --- | --- |
| `terrain_atk_mult` / `terrain_def_mult`（dict） | 每级相加 | 林地战法 L3 = 森林防御 +15% |
| `atk_bonus / flank_bonus / capture_bonus / plot_bonus / output_bonus ...`（标量加成） | 每级相加 | 平原战法 L5 = 攻击 +10% |
| `resource_output_mult` / `node_type_output_mult`（乘区） | 每级相乘 | 谷田精耕 L5 = 粮草 ×1.216 |
| `morale_loss_mult` / `fire_def_mult` 等 `<1` 乘区 | 每级相乘 | 士气整训 L5 = ×0.904 |
| bool（`ignore_zoc` 等） | 等级 ≥1 即真 | 主脉 L7 已给，支脉不再重复 |

> 下游 `_army_sim`、`_sim_view`、`_step_distribute_output`、计略、俘获等只读扁平键，**无需改动**。

### 5.3 解锁与升级规则

| 场景 | 规则 |
| --- | --- |
| 主脉第 k 节 | `tech[line] == k - 1` 才可研究；完成 `tech[line] += 1` |
| 支脉 | 父主脉已完成（`tech[line] >= parent.spine`）才解锁；等级 `< max` 可继续研究 |
| 已满级 | 按钮置灰「已满级」 |
| 前置未解锁 | 卡片置灰「需先完成 X」 |
| 已有研究 | 其余节点全部禁用，显示剩余时间 |
| 未任职 | 无官职玩家只读，不能点研究（沿用现有 `OFFICER_POSITIONS` 校验） |

## 12. 一句话总结

> 把「三条线性进度条」改成「三条主脉 × 每节挂 2~3 条可连点支脉」的树：主脉负责**解锁类别**，支脉负责**同类叠加**；数据上只新增 `tech_json.nodes`，效果仍汇入现有 `tech_effects()` 扁平键，后端下游与旧存档零改动，前端把三行表格换成可折叠树形卡片。
