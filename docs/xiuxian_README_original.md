## 🚀 部署与上机自检

### 依赖
```
aiosqlite>=0.19.0
Pillow>=9.0.0
```

### 部署前离线自检（本机有 Python 即可，无需 AstrBot）
```
py -3 -X utf8 _final_check.py      # 全局体检：语法/指令覆盖/配置键/资源/版本
py -3 -X utf8 tests\test_core_logic.py   # 13 项核心逻辑单测
py -3 -X utf8 _test_render.py      # 卡片渲染冒烟（生成真实图片）
py -3 -X utf8 _test_events.py      # 110 个奇遇事件结构校验
```

### 上机实测清单（按优先级）
1. **启动**：老库自动迁移到 v28；观察日志无 ERROR；`【修仙插件】已加载`
2. **崩溃修复回归**：`/接收` 赠予、`/放生灵兽`、`/一键日常`（签到是否落库）
3. **图片卡片**：`/我的信息` `/签到` `/储物戒` `/我的装备` `/我的灵田` `/丹阁` `/坊市` 是否出图（Pillow 未装时自动降级纯文本）
4. **经济链路**：购买→资费突破→丹劫→押镖→劫镖（冷却/赔偿）
5. **全服事件**：配置 `WHITELIST_GROUPS` 后测试 `/开启魔潮` 广播与 `/抵御魔潮` 进度条
6. **管理员**：配置 `BOSS_ADMINS` 后测试 `/仙界管理 查玩家`

### 常见问题
- **全服事件无广播** → 未配置白名单 `WHITELIST_GROUPS`（日志会输出醒目警告）
- **图片不出** → 检查 Pillow 安装与 `resources/` 目录完整性；WebUI 中 IMAGE_CARDS 开关
- **老库升级失败** → 查看日志 `数据库升级失败: vN`，迁移已幂等（重复列自动跳过）

## 🆕 v6.8 新玩法 (2026-10-24)

### ⚔️ 五行克制（战斗深度）
功法/心法/武器名称中含 **金木水火土** 即获得对应五行属性（优先主修心法）。金克木、木克土、土克水、水克火、火克金：**克制方伤害 +30%，被克方伤害 -20%**。世界Boss也会随机携带五行属性——出战前选对属性功法，平民也能越阶挑战。

### ⚡ 丹劫机制（炼丹扩展）
境界需求 ≥6 的高阶丹药出炉时有 **25% 概率引来丹劫**：携带【引雷符】可引雷淬丹保住成果，没有则丹药当场化为灰烬（材料照扣）。引雷符百宝阁有售。

### 🌾 灵田杂交与肥力
- **土壤肥力**：每次收获消耗肥力（每株-8，最低20），肥力直接打折产量；发送 `/施肥` 消耗2000灵石恢复30点。
- **杂交嫁接**：`/杂交 火焰花 冰心草`，50% 概率培育出天阶灵草【冰火双生花】（修为+25000/株）。

### 💎 储物戒空间附魔
`/储物戒附魔 [数量]` 消耗【空间石】（百宝阁有售），每颗永久 +5 容量，上限 +50。附魔加成跟随玩家，换戒指也不消失。

### 🛡️ 押镖与劫道（全新系统）
- `/押镖`：接一趟30分钟的灵石镖，镖银随境界浮动，期间处于押镖状态并**全服广播**。
- `/完成押镖` 送达领全款；`/放弃押镖` 跑路无收益。
- `/劫镖 @某人`：消耗【迷神香】触发强制PVP（押镖人气血先打8折），胜者抢走30%镖银，败者赔偿1000灵石。

### ✨ 奇遇选项系统（Roguelike）
历练归来有 20% 概率触发奇遇事件（上古洞府/重伤道人/无名灵酒）：机器人给出三选一，发送 `/奇遇选择 <编号>` 结算——强行破门可能拿神装也可能重伤，救人得善报，拿储物袋遭反噬。2分钟不选视作离开。

**数据库升级至 v27**（灵田肥力字段），旧库启动时自动迁移。

## 🔧 v6.0.1 修复内容 (2026-10-24)

### 崩溃类修复
- **数据库迁移**：老库升级时 v11/v12 的 `ALTER TABLE` 因重复列必然失败导致插件无法启动，现已改为幂等加列（先检查列是否存在）；同时防御了 `BEGIN` 事务嵌套报错
- **接收赠予**：修复属性名错误（`storage_ring_mgr` → `storage_ring_manager`）与未导入 `logger` 导致 `/接收` 必崩的问题
- **灵兽系统**：补齐 `/放生灵兽`、`/吞噬灵兽` 缺失的处理器方法，指令不再报 AttributeError
- **储物戒**：取出/丢弃物品时玩家数据不存在（如已被追杀删除）不再空指针崩溃
- **世界Boss(旧)**：属性计算异常分支的变量未定义不再 NameError，战报血条上限与实际 HP 口径统一
- **商店数据**：`current_items` 为 NULL 时不再抛 TypeError

### 逻辑/经济类修复
- **一键日常**：签到奖励此前可能因未落库而丢失（且次日可重复签），现已即时持久化
- **换装**：旧装备存入储物戒失败时不再凭空消失，改为中止换装并提示清理储物戒
- **突破**：无效/不适用破境丹不再被白白消耗，先校验后扣丹
- **决斗**：冷却（5分钟）真正生效；仅胜利方计入 `win_pvp` 任务进度（此前输赢都算）
- **切磋**：冷却（1分钟）真正生效
- **洞府掠夺**：被偷方只损失被偷走的 15% 产出，不再全部挂机收益蒸发
- **新角色**：灵修初始灵气不再可能超过上限；灵根权重支持浮点配置
- **日常任务**：过期任务自动清理，不再永久占用每日接取上限
- **悬赏/系统配置**：查询不再每次内嵌 DDL+commit 破坏外层事务原子性
- **商店展示**：售罄物品跳过后序号连续；折扣文案改为中文习惯（如 8折）
- **灵眼**：信息页待收取收益改用上次收取时间计算，不再虚高
- **宗门**：被踢成员职位归零，与主动退宗一致
- **丹药**：满状态服用全恢复类丹药不再虚报恢复量

## 📦 配置与部署

1. 确保已安装 AstrBot。
2. 将插件放入 `data/plugins/astrbot_plugin_xiuxian_promax`（本仓库：[iqapi/astrbot_plugin_xiuxian_promax](https://github.com/iqapi/astrbot_plugin_xiuxian_promax)）。
3. 安装依赖：`pip install -r requirements.txt`（包含 `aiosqlite` 和 `Pillow`）。
4. 启动 AstrBot，插件会自动创建 `config/` 目录并生成海量物品数据（多达 1500+ 种）。
5. **从旧版（astrbot_plugin_monixiuxian2 / astrbot_plugin_xiuxian）升级**：首次启动会自动把旧数据目录整体迁移到新目录，玩家数据无缝保留。

**⚠️ 重要提示（关于数据库）**：
插件底层已升级至 `v28` 版本（灵田肥力 / 功德 / 生活职业 / 洞天家具 / 宗门建筑字段）。从任何旧版本升级都会自动无缝迁移，迁移已做幂等处理（重复列自动跳过）。如果你在测试中遇到任何卡死，直接发送 `/解卡` 指令强制重置状态。

## 🛠️ 底层架构优化（对比原版）

1. **并发保护**：全面引入了 `BEGIN IMMEDIATE` 事务锁，并提供 `_scan_tx.py` 静态扫描防止嵌套事务；买丹药、存钱、领任务奖励等操作彻底杜绝连点器刷资源。
2. **原子增量更新**：`update_player_fields` / `add_player_gold` / `add_player_exp` 精准更新字段，消除全字段覆盖导致的并发回滚；领利息带乐观校验事务化。
3. **状态互斥熔断**：通过 `utils.py` 的白名单机制，杜绝玩家在"闭关"或"历练"时卡 bug 去干别的事。
4. **经济生态闭环**：任务/Boss/活动产出绑定材料；交易、赌石、黑市、银行收取利息和税金；突破资费形成额外回收口，稳定全服物价。
5. **物品池安全过滤**：所有随机掉落从配置文件动态读取，不会产生"幽灵物品"；依赖物品（引雷符/空间石/化身傀儡等）由 `_final_check.py` 自动对账。
6. **离线质量保障**：13 项核心逻辑单测 + 110 事件结构校验 + 卡片渲染冒烟 + 全局体检（语法/指令覆盖/配置键/资源），改动后一键回归。

- **改代码后必跑**：`py -3 -X utf8 _final_check.py`（全局体检）+ `py -3 -X utf8 tests\test_core_logic.py`（单测）
- **数据库**：新字段一律走 `_add_column_if_missing` 幂等迁移，并同步更新 `models.py` 的 dataclass、`update_player`/`create_player` SQL、`LATEST_DB_VERSION`
- **新增指令**：在 `main.py` 注册后务必更新 `misc_handler.py` 的 `/修仙帮助`（体检脚本会自动对账）

- **新界面图片化**：调用 `utils.image_generator.render_card` + 在 `_conf_schema.json` 的 IMAGE_CARDS 加开关
- **版本规范**：功能更新同步 bump `metadata.yaml`、README 标题与帮助菜单版本号（遵循 AGENTS.md）
