# 预期效果与命令呈现映射

> 配套方案：`呈现层设计方案v3_结构化直通.md`
> 本文定义「做完之后长什么样」以及「每个命令落在哪里」，作为验收依据。

## 一、三个界面状态

1. **桌面端**：左聊天流（人话 + 动作反馈 + 播报横幅）+ 右常驻看板（状态/储物戒/指令三 Tab）
2. **移动端**：单列全屏聊天 + 底部四 Tab，点 Tab 从底部弹 85% 高抽屉
3. **全屏状态**：图片兜底内容可双指缩放；参数输入用底部小弹层

## 二、呈现形态定义（6 种）

| 代号 | 形态 | 说明 |
|------|------|------|
| C1 | 看板卡片 | 结构化数据 → 原生卡片（分区、进度条、指标、装备槽），进看板不进聊天流 |
| C2 | 消息卡片 | 需要留在聊天上下文里的结构化内容（如灵根选择、榜单）→ 聊天流内卡片，可折叠 |
| C3 | 动作气泡 | 纯文本动作结果 → 气泡 + 语义色边（成功绿 / 失败红 / 警告橙） |
| C4 | 播报横幅 | 全服事件 → 聊天流顶部横幅，带动作按钮，自动淡出 |
| C5 | 参数弹层 | 需要参数的指令 → 底部弹层输入，带用法提示 |
| C6 | 原图 | 无结构化数据的图片（海报/截图）→ 图片 + 全屏查看 |

## 四、单条命令的完整体验示例：`/突破`

```
1. 用户点状态看板底部「突破」
2. 前端发 {action:"cmd", text:"/突破信息", private:true, req_id:"x7"}
3. 回复进看板：突破预演卡（成功率 62% / 消耗 500 灵石 / 失败损失 20% 修为）
4. 卡片底部按钮「确认突破」→ 发 {action:"cmd", text:"/突破", req_id:"x8"}
5. 结果：
   成功 → 看板境界徽标滑升一级 + 修为条归零 + 聊天流金色气泡"突破成功"
   失败 → 红色气泡展示损失，看板修为条下移到 80%
6. 全过程聊天流只有 1 条气泡，其余都在看板
```

## 五、与 QQ 端对比

| 维度 | QQ 端现在 | 网页端之后 |
|------|----------|-----------|
| 查信息 | 全群可见的图片，刷屏 | 只发给自己，进常驻看板 |
| 卡片可读性 | 图片需点开放大 | 原生文本随屏宽重排 |
| 卡片交互 | 无 | 物品/槽位/按钮可点 |
| 长文本 | 一大段，难扫读 | 分区卡片 + 折叠 |
| 播报 | 混在消息流里被淹没 | 置顶横幅，可回看 |
| 指令 | 需要记 257 条 | 搜索 + 分类 + 最近使用 |
| 带宽 | 单卡片 276KB | 约 2KB |
