# 网页端看板与指令按钮设计方案 v2（含移动端）

> v2 修订：补入设计审阅结论 + 移动端完整方案。v1 设计中的「卡片塞进右侧看板栏」经实测证伪，已修正。

## 一、v1 设计审阅：发现 6 个问题

| # | 问题 | 严重度 | 结论 |
|---|------|--------|------|
| 1 | **卡片图塞不进看板** | 🔴 致命 | 实测 `/我的信息` 卡片为 **1000×2804（1:2.8）**。右侧栏宽 300px 时正文约 4px；手机 390px 宽时约 5px，完全不可读。v1 的"面板内显示卡片图"不可行 |
| 2 | **私聊回复缺少请求关联** | 🔴 高 | 只看 `private:true` 无法区分「刷新两次」或「两个面板同时请求」的回复归属，会串面板。必须带 `req_id` 回传 |
| 3 | **自动刷新成本被低估** | 🟠 中 | 每次查信息=插件跑一次 HTML 渲染 → 276KB JPG。定时轮询会让服务器持续做图片渲染。改为**按需触发**（打开面板/点刷新/操作后） |
| 4 | **多步指令流程断了** | 🟠 中 | 按钮只能发单条指令。注册流程（选职业→选灵根）、突破确认等需要连续输入，纯按钮 UI 会卡住 |
| 5 | **移动端 100vh 与键盘** | 🟠 中 | `height:100vh` 在手机浏览器会被地址栏/键盘遮挡，输入框可能被顶出屏幕 |
| 6 | **在线列表占宽度** | 🟢 低 | 150px 侧栏在手机上等于砍掉 40% 聊天宽度 |

## 二、修正后的核心设计

### 2.1 看板改为「抽屉 + 缩略图 + 全屏缩放」

- 桌面：右侧 420px 抽屉（可收起），移动端：底部抽屉，默认 85% 屏高
- 抽屉内卡片只显示**缩略图**（宽度撑满、高度上限 40%），角标「⊕ 放大」
- 点按 → 全屏查看器：图片按原生 1000px 渲染，支持双指缩放 / 双击放大 / 拖动，桌面支持滚轮缩放
- 理由：卡片是位图、含大量小字，唯一可读路径是"能放大"。这样既保留插件零改动的优势，又解决可读性

### 2.2 私聊通道（带请求关联）

```
客户端 → {action:"cmd", text:"/储物戒", private:true, req_id:"c3-17"}
服务端 → 记录 pending: req_id ↔ player_id，进流水线
回复   → bot 消息带 req_id，只发给该玩家连接
客户端 → req_id 命中 → 渲染到对应面板 / 快选项区；未命中 → 普通聊天气泡
```
超时 15s 未收到回复则清空 pending，面板显示"请求超时，点击重试"。
指令仍走完整 AstrBot 流水线，**插件不改**。

### 2.3 多步指令：智能快捷选项

机器人回复里出现明确的交互提示时（如 `请发送：选择灵根 1/2/3`、`请发送：接受切磋`），前端从文本里**尽力提取**可选项，渲染成一行可点按钮（无需打字）：

- 匹配规则集中在 `quickOptions(text)` 一个函数里，识别 `请发送：X 1/2/3`、`选择 X`、`A/B` 等常见句式
- 识别失败不影响使用——用户仍可手打
- 定位为"锦上添花"，不做硬保证；彻底解决要靠 M3 的结构化返回

### 2.4 不再定时轮询

打开面板 / 点刷新 / 完成一次操作后各触发一次；同一玩家 10 秒内重复请求直接复用上次结果（前端缓存 + 时间戳）。

## 三、移动端方案

### 3.1 布局（断点 768px）

```
移动端：单列全屏
┌────────────────────┐
│ room_main ·3人在线 ● │  ← 顶部极简栏（在线列表点开才显示）
├────────────────────┤
│                    │
│    消息流（100%）    │
│                    │
├────────────────────┤
│ [说话或输入指令] ﹢  │  ← 输入栏，跟随键盘
├────────────────────┤
│ 聊天 状态 储物戒 指令 │  ← 底部四 Tab（≥44px 触控高）
└────────────────────┘
点 Tab → 底部抽屉从下弹出（85% 高），聊天区仍可见
```

桌面端：左聊天 + 右 420px 抽屉（抽屉默认收起，点 Tab 展开）。

### 3.2 移动端必须处理的细节

| 项 | 做法 |
|----|------|
| 视口高度 | `100dvh` + `visualViewport` 监听，键盘弹出时输入栏贴着键盘上沿 |
| 安全区 | `padding-bottom: env(safe-area-inset-bottom)`（iPhone 刘海/小白条） |
| 触控尺寸 | 所有可点元素 ≥44×44；按钮间距 ≥8px；禁用 hover 依赖 |
| 消息宽度 | 移动端 88%（桌面 78%） |
| 在线列表 | 收起为顶部数字角标 + 点开浮层 |
| 图片查看 | 全屏查看器 + 双指缩放 + 双击放大；避免误触长按菜单 |
| 断线恢复 | `visibilitychange` 回前台立即重连；本地缓存最近 100 条消息，重连后补齐上下文 |
| 移动网络 | 卡片图加轻量预览（服务端生成 640px 缩略图），全屏查看再取原图 |
| 输入法 | 中文输入法 composition 期间不触发 Enter 发送（`isComposing` 判断） |

### 3.3 移动端不做的事

- 不做横屏专门适配（横屏沿用桌面布局）
- 不做手势滑动切 Tab（与系统返回手势冲突）
- 不在移动端展示全部 257 指令（抽屉内只放 30 个高频，其余用搜索框）

## 四、实现顺序（修订版）

| 步骤 | 内容 | 验收 |
|------|------|------|
| S1 | 私聊通道（req_id + 定向回复） | 两人同房间，各自点「我的信息」互不看见 |
| S2 | 抽屉骨架 + Tab 切换 + 移动端底部导航 | 手机宽度下聊天/看板可切换，键盘不遮挡输入 |
| S3 | 看板内容：缩略图 + 全屏缩放查看器 + 刷新/超时态 | 卡片放大后文字清晰可读 |
| S4 | 指令按钮网格（高频/分组/带参弹框） | 点「购买」弹输入框，确认后发送 |
| S5 | 智能快捷选项 + 断线恢复 + 本地历史 | 注册流程全程点选可完成 |

## 五、遗留风险

1. **卡片位图不可交互**：看板里的卡片仍是一张图，点击物品无法直接操作——只能靠 M3 的 JSON 接口解决
2. **房间无鉴权**：现在知道 URL 就能进任何房间，玩家身份靠自报道号，可顶号。上线前需加房间口令或登录（M3）
3. **顶号机制**：同名玩家会被挤下线，移动端切换网络重连时可能被自己顶掉，需用 `player_token` 区分会话（S5 一并处理）
4. **`register_platform_adapter` 是 core API**：AstrBot 升级可能变动，锁定 4.29.x

## 六、M3（真正解决可读性/交互性）

插件侧增加内部数据出口（复用 handler 内部查询函数，不经过图片渲染），返回结构化 JSON：
- 我的信息 → 属性、境界、修为进度、装备槽、宗门
- 储物戒 → 物品列表（可点击使用/装备/取出）
- 世界Boss/秘境 → 状态与倒计时

前端原生渲染：实时数值、进度条、可点击物品、倒计时。届时看板才真正"活"起来，图片卡片降级为「截图分享」用途。
