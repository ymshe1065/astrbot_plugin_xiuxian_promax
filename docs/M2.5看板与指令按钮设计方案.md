# 网页端看板与指令按钮设计方案（M2.5）

> 前置：M1 核心链路已完成（webroom 适配器 + WS 房间服务 + 网页聊天 UI）。
> 本方案解决两件事：回复格式适配网页 + 看板/按钮交互设计。

## 一、格式问题诊断结论

| 现象 | 根因 | 状态 |
|------|------|------|
| 回复文字挤成一坨、没有换行 | `.msg` 样式缺 `white-space: pre-wrap`，HTML 把 `\n` 折叠成空格 | ✅ 已修（commit b01a51a） |
| 信息类指令只显示一张图没有文字 | `/我的信息`、`/储物戒` 等 40+ 指令的回复本身就是插件渲染的**信息卡片图**（QQ 端也是发图，非文本） | 由本方案看板承接 |

关键事实：**信息看板的"数据源"目前只有图片**。插件 257 个指令的回复分两类：
- 纯文本（emoji + ━━━ 分隔线 + 缩进结构）——网页 `pre-wrap` 后显示效果可接受
- 图片卡片（我的信息/储物戒/装备/丹药背包/排行等）——本来就是为竖屏聊天设计的渲染图

## 二、整体布局

```
┌─────────────────────────┬──────────────────┐
│                         │ [状态][储物戒][指令] │
│      聊天区（现有）        │ ┌──────────────┐ │
│                         │ │ 看板内容区      │ │
│  玩家消息 / 世界播报       │ │ (图片卡片/列表) │ │
│  群聊语义不变             │ └──────────────┘ │
│                         │ 快捷指令按钮网格    │
└─────────────────────────┴──────────────────┘
移动端：底部 Tab 切换「聊天 / 看板」两个全屏页
```

## 三、核心机制：私聊通道（必须做）

现状问题：所有回复广播全房间——A 点「我的信息」，B 也看得到 A 的卡片图，**又吵又泄露信息**。

设计：新增消息动作 `action:"cmd"` + `private:true`：
```
客户端 → {action:"cmd", text:"/储物戒", private:true}
服务端 → 该玩家消息进流水线，但 bot 回复只回传给请求者的连接
       → 客户端识别 private 回复 → 渲染到看板面板（不进聊天流）
```
实现点：`room_server` 广播函数加 `target_player` 参数；适配器记录 pending 私聊请求（player_id → 标记），`WebroomMessageEvent.send()` 按标记决定广播或定向。指令仍走完整流水线，**插件零改动**。

## 四、看板设计（3 个 Tab）

### Tab1 状态
- 主体：`/我的信息` 卡片图（私聊返回），点「刷新」重新请求
- 辅按钮：我的装备 / 我的状态 / 心法 / 技能 / 突破信息（点击→卡片图区切换显示）
- 状态徽标：境界/修为从图片无法解析 → M3 JSON 接口后再做实时徽标，本版不做

### Tab2 储物戒
- 主体：`/储物戒` 卡片图 + 刷新
- 辅按钮：丹药背包 / 更换储物戒
- 带参数操作走输入框：取出 X、装备 X、服用丹药 X、回收 X（点击弹小输入框，确认发送）

### Tab3 指令（按钮网格，按使用频率分三档）
| 档位 | 指令（示例） | 交互 |
|------|------|------|
| 高频（置顶大按钮） | 签到、闭关、出关、调息、世界Boss、挑战Boss | 点按即发 |
| 中频（分组折叠） | 丹阁/符阁/器阁/百宝阁、宗门列表、秘境列表、境界/战力/灵石排行 | 点按即发 |
| 带参（点击弹输入框） | 我要修仙 <职业>、选择灵根 <n>、购买 <物品>、搜索物品 <关键词>、赠予 <人> <物品> | 小输入框确认 |

按钮分组默认收起，仅展开当前组；参数按钮弹层内带用法提示（从指令描述取，如"10 分钟内有效"）。
按钮配置集中为一个 JS 常量数组，后续加指令只改配置不改逻辑。

## 五、不做 / 后续演进

- **不做**：把 257 个指令全铺出来——新手会被淹没，M2.5 只覆盖 30 个以内常用指令
- **M3 JSON 数据接口**：插件侧加内部数据导出（复用 handler 内部查询函数），看板原生渲染：实时属性徽标、储物戒可点击物品直接操作、突破/闭关倒计时条——体验质变，但要动插件内部，单独排期
- 世界播报接入公屏（路线 B 方案 M2 既定项，与本方案并行实现）

## 六、验收标准

1. 看板点「我的信息」→ 仅自己看到卡片图渲染在看板内，公屏无动静
2. 点「签到」→ 公屏发出消息，机器人回复正常进聊天流
3. 点「购买」→ 弹输入框，输入确认后发送 `/购买 xxx`
4. 手机宽度下聊天/看板可切换，图片自适应面板宽度
