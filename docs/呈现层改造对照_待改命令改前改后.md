## 一、怎么读这份文档

### 1.1 三条硬口径

1. **「改前」是源码原文，不是我的复述。** 每段改前都标注了出处（`文件:行号`），变量保留 `{xxx}` 形态；
   少数带真实数值的段落来自测试夹具实跑（标 `实测`）。
2. **「改后」以块结构为主，附网页排版示意。** 每段改后包含
   - **块结构**：`ViewModel` 里放哪几种原子块、各带什么字段；
   - **网页**：排版示意（分组、对比、可点区域）；
   - **QQ**：统一由 `render_text()` 输出，**要求与改前逐字一致**（v4 §9.4 硬约束），
     所以下文不再逐条重画 QQ 版式，只在有增删时单独注明。
3. **改后不是「更好看」，是「信息可判定」。** 判断标准只有一条：
   **玩家看完这条回复，下一步该点哪里，是不是不需要再记指令。**

### 1.2 待改范围（131 条）

| 类别 | 条数 | 处置 |
|---|---|---|
| 查询与面板类 | 122 | 本文逐条对照，目标块见第三/四章 |
| 带前后数值对比的动作（强化/洗练/炼丹/制符/突破/飞升/炼器/切原石/赠予） | 9 | 同上，形态固定为 `note + compare/stats` |
| **合计待改** | **131** | |
| 纯动作回执（签到/购买/加入/领取…） | 130 | **不改结构**，只统一 `note` 样式（见第六章） |
| 合计 | 261 | 与 `@filter.command` 计数一致 |

> 判定口径：动作动词表命中即归「回执」，但 `QUERY_FORCE` 白名单（`突破信息`/`我的装备`/`可制符箓`/`奇遇选择`/
> `选择灵根`/`选择生活职业`/`丹药背包`/`丹药信息`/`符箓`）强制归「查询」——它们虽然有动词，
> 实际返回的是面板或菜单。规则写在 `scripts/gen_render_table.py`，可复跑。

### 1.3 为什么不是「全都要改」

130 条动作回执本来就该是一句话。它们的毛病是**样式散**（有的以 ✅ 开头，有的以 ✨ 开头，有的带三行分隔线），
不是**结构错**。给它们套 `table` 反而是过度设计。这一点在第六章展开。

### 2.1 八条跨组结论

1. **越靠「列表」越糟。** 17 组里 12 组的主症状是「同一行塞多个字段」或「层级被拍平」。
2. **越靠「数值决策」越糟。** 突破、强化、炼丹这类「花资源换概率」的动作，界面从不做对比。
3. **零卡片的组恰好是最需要表格的组。** 宗门 26/26、排行 10/10、钱庄 8/8 全是纯文本。
4. **同一份数据在两处长得不一样。** `/我的信息` 的战力与 `/战力排行` 的战力同源，但一处是键值、一处是句号句。
5. **提示语承担了本该由控件承担的工作。** `💡 /秘境列表 灵植 / 矿材 … 按产物筛选` —— 这是筛选器，却写成了说明书。
6. **`|` 与 ` · ` 是事实上的列分隔符。** 全项目 40+ 处用它们拼两个字段，但前端没有列概念。
7. **进度条只出现在三个地方**（魔潮、宗门建筑、灵田），其余进度全是「8420/12000」。
8. **所有「当前无法操作」的原因都没有归因。** 只说「材料不足」，不说缺几个、去哪补。

**同样没有「效果」，而且这里连底层数据都是坏的。** 三层问题，逐层都要修：

| 层 | 实测 | 结论 |
|---|---|---|
| 配置 | 692 条 `desc` **全部**是 `记载XX炼制方法的丹方。` | 443 个不同的废话模板，一个字的效果都没有 |
| 代码 | `_generate_pill_desc()` 能把配置翻成 `增加500修为（凡品修为丹）` | **是死代码**：`_normalize_recipe` 里 `if not desc` 才调它，而 692 条全都有 `desc` |
| 数据 | 249 / 692（36%）的 `output_pill` 能在 `exp_pills`/`utility_pills`/`pills` 里查到效果 | 443 条（64%）**没有任何效果定义** |

拿 130 号当例子，代码里其实是能算出真效果的：

```

## 六、不改结构的那 130 条：只做「一个 note」

**现状的三种写法并存：**

```
✅ 已购买 回春散 ×5，花费 1,230 灵石
```
```
✨ 你开始执行宗门任务！任务需要1小时完成，请在完成后使用 /完成宗门任务 领取奖励。
```
```
━━━━━━━━━━━━━━━
🎊 签到成功
━━━━━━━━━━━━━━━
获得：灵石 ×200
连续：7 天
━━━━━━━━━━━━━━━
```

**统一成 `note` 一条**：`{icon, text, tone: success/warn/info, delta?: [{k, v}]}`，
文本端输出 `✅ 已购买 回春散 ×5，花费 1,230 灵石`（逐字不变），网页端渲染成一条带色边的回执条，
`delta` 存在时在右侧追加变化量（`灵石 -1,230`）。

**唯一例外**：`/强化` `/洗练` `/炼丹` `/制符` `/突破` `/飞升` `/炼器` `/切原石` `/赠予` 九条，
因为「成功/失败 + 前后差值」本身就是决策信息，形态为 `note + compare`。
