# 呈现层设计方案 v3：结构化直通

> v3 推翻 v1/v2 的「把图片卡片塞进看板再放大」思路。
> 关键发现：**卡片不是图片，是被拍平成图片的数据**。已实测验证并落地 sidecar。

## 一、关键发现（已实测）

1. 插件所有信息卡片由 `utils/image_generator.py: render_card()` 用 **Pillow 绘制**，不是 HTML 截图——没有 HTML 可截胡，但有**更好的东西**。
2. 14 个调用点传入的都是结构化数据：
   ```python
   render_card_async("info", 道号, "ID: xxx · 境界",
       sections=[{"name": "基础", "rows": [("境界", "炼气期一层"), ("修为", "0/500"), ...]}, ...],
       footer="模拟修仙 · 发送 /修仙帮助 查看全部指令")
   ```
3. 单点落盘，可无损附挂结构化 sidecar。已在 `render_card()` 加 15 行：落图同时写同名 `.json`。
4. **实测抓到的真实数据**（我的信息）：
   ```
   title=格式诊断员  subtitle=ID: web_格式诊断员 · 炼气期一层
   基础(11) 属性(5) 战斗(8) 装备与宗门(12)  = 36 行键值
   修为 0/500 · 灵石 1,100 · 战力 403 · 气血 1,280/1,280 · 8 个装备槽
   ```
5. 卡片图 1000×2804 / 276KB；同一份数据的 JSON 约 2KB。**信息量相同，体积 1/130。**

## 二、结论：呈现层应该基于数据，不是基于图片

QQ 端必须发图，因为 QQ 消息没有排版能力。网页端没有这个限制——把数据画成图再让浏览器显示图，是纯粹的信息损失。

### 2.1 四类内容 → 四种呈现形态

| 内容类型 | 数据来源 | 呈现形态 | 位置 |
|---------|---------|---------|------|
| **查询卡片**（我的信息/储物戒/装备/丹阁/器阁/宗门/宠物/Boss） | sidecar JSON（14 处） | 原生卡片（分区+数值+进度条） | 看板常驻 / 抽屉 |
| **长文本回复**（200+ 指令） | 文本方言 | 文本解析 → 原生卡片 | 聊天流（可折叠） |
| **动作反馈**（签到/闭关/突破/购买） | 纯文本 | 气泡 + 结果样式（成功/失败/警告） | 聊天流 |
| **世界播报**（Boss/秘境/拍卖） | 纯文本 | 置顶横幅（自动淡出） | 聊天流顶部 |
| **无结构图片**（海报/截图） | 图片 | 图片 + 全屏查看 | 聊天流 |

**核心决策：查询类内容不进聊天流。** 这正面回答了你最初的问题——QQ 群里刷屏的根源就是"所有查询结果都挤在消息流里"。网页端把查询搬到常驻看板，聊天流只留人话和动作反馈，刷屏问题从呈现层根治。

### 2.2 原生卡片渲染规格

**头部**：道号 + ID 副标题 + 境界徽标 + 更新时间 + 刷新图标
**主指标区**（从 rows 提升）：灵石 / 战力 / 气运 → 三宫格大数字（等宽字体）
**进度区**：值形如 `a/b` 且两侧是数字 → 进度条（修为、气血、灵气）
**装备槽**：`武器/头饰/甲胄/手套/靴子/戒指1/戒指2/护符` → 4×2 槽位网格，空值显示虚线空槽，可点击
**其余分区**：两列键值网格；行数 >8 的分区默认折叠，"展开全部"
**底部操作行**：按状态给快捷动作（闭关/收功/签到/突破）

数值语义规则（集中在一个 `formatValue(label, value)` 里）：
| 形态 | 处理 |
|------|------|
| `1,280/1,280` | 进度条 + 分数标签 |
| `1,100` | 千分位等宽数字 |
| `+0.0%` / `-3` | 涨跌色（跌用绿色，符合中文习惯） |
| `无` / `—` | 灰色占位 |
| `【神话】【上品】凡品` | 品质色标签 |
| 其他 | 常规文本 |

### 2.3 交互（这是原生渲染带来的真正增量）

- **储物戒物品**：`(物品名, x3)` → 物品芯片，点击弹操作：装备 / 取出 / 回收 / 赠予 → 自动填参发送
- **装备空槽**：点击 → 提示"可装备的物品"（需 M3 数据）→ 当前降级为发 `/我的装备`
- **修为条**：点击 → 提示"距突破还需 500 修为"+「闭关」按钮
- **行动区**：根据 `状态=空闲/闭关中` 切换按钮组合（闭关 / 收功）
- **参数指令**：点击弹小输入框，带用法提示（如"10 分钟内有效"）

### 2.4 移动端

原生卡片是文本流，随屏宽重排 —— **v2 里"必须全屏缩放才能读"的问题自动消失**。

| 项 | 做法 |
|----|------|
| 布局 | 单列全屏 + 底部四 Tab（聊天/状态/储物戒/指令），点 Tab 底部抽屉 85% 高 |
| 视口 | `100dvh` + `visualViewport` 监听，键盘弹起时输入栏贴键盘 |
| 安全区 | `padding-bottom: env(safe-area-inset-bottom)` |
| 触控 | 可点元素 ≥44×44，间距 ≥8px，无 hover 依赖 |
| 手势 | 卡片分区可折叠；图片（仅兜底类）双指缩放 |
| 断线 | `visibilitychange` 回前台重连 + 本地缓存最近 100 条 |
| 输入法 | composition 期间不触发发送 |

## 三、实施顺序

| 步骤 | 内容 | 状态 |

| S0 | 卡片 sidecar（`image_generator` 落图同时写 JSON，清理同步） | ✅ 已完成 |

| S2 | 前端卡片渲染器：JSON → 原生卡片（含数值规则、分区折叠） | 待做 |
| S3 | 看板常驻 + 抽屉布局 + 移动端底部导航 | 待做 |
| S4 | 交互：物品芯片、装备槽、行动区、参数弹层 | 待做 |
| S5 | 文本方言解析（`━━━` 分区 / `【】` 标签 / `键：值` / 列表） | 待做 |
| S6 | 播报横幅、动作气泡样式、断线恢复、本地历史 | 待做 |

验收：
1. `/我的信息` 不再返回图片，看板显示原生卡片，修为是进度条
2. 手机宽度下卡片文字正常大小、无需缩放
3. 储物戒物品点击 → 弹操作 → 自动发送指令
4. 两人同房间各自查信息互不可见（私聊通道生效）

## 四、风险与待解决

1. **临时目录**：卡片存系统 temp（`%TEMP%/xiuxian_cards`），重启可能被清；Web 端读取前需迁移到 `data/cards`（S2 一并处理）
2. **卡片+文本双发**：部分 handler 出图后又 yield 文本（如新手引导），需去重策略：卡片优先，文本中的提示类保留为卡片脚注
3. **语义缺失**：payload 只有 label/value，没有"这是物品/这是进度"的类型标记。先靠启发式（label 关键词 + value 格式），关键卡片（我的信息/储物戒）可在 sections 里可选加 `kind` 字段精确标注
4. **房间无鉴权**：知道 URL 即可进任意房间、可自报道号顶号。上线前需口令或登录
5. **`register_platform_adapter` 是 core API**：锁 AstrBot 4.29.x
